## 4. 지시서 넘기는 방법

지시서는 `05_Docs/WorkOrders/` 에 있다. **자기완결**이라 다른 기획서를 같이 주지 않는다. 규격 `V01` 만 함께 준다.

```
이 지시서대로 구현해줘: D:\UnityProject\3D\QuarantineLine\QuarantineLine\Assets\05_Docs\WorkOrders\L01_프로젝트_골격.md
규격은 이거 따라: D:\UnityProject\3D\QuarantineLine\QuarantineLine\Assets\05_Docs\V01_구조_규격.md
세션 규칙은 이거: D:\UnityProject\3D\QuarantineLine\QuarantineLine\Assets\05_Docs\Sessions\S1_코어로직.md
```

지시서는 **바로 앞 작업이 검증 통과한 뒤** R1 이 쓴다 (순차 개발이라 앞 작업 결과를 반영해야 한다). 지금 작성된 지시서는 `L01` 하나다.

## 5. 공통 규칙 (모든 개발 세션)

1. 지시서와 `V01` 만 보고 구현한다. **지시서에 없는 기능은 넣지 않는다**
2. **소유 파일만 수정한다.** 남의 파일을 고쳐야 하면 고치지 말고 「전달 요청」으로 남긴다
3. 수치를 코드에 직접 쓰지 않는다. 전부 ScriptableObject(`V01` 4장)에서 읽는다
4. 옛 `UnityEngine.Input` 금지 — 이 프로젝트는 `activeInputHandler: 1`(Input System 전용)이다
5. 커밋·푸시는 사람이 `/finish` 할 때만 한다
6. 끝나면 ① 완료 체크리스트 결과 ② 검증 항목 (📷 사진 · 🖐 손맛으로 나눠서) ③ 전달 요청 을 출력한다

## 5.1 검증 3단계 (사람 결정 2026-11-10)
지시서의 확인 항목은 R1 이 셋 중 하나로 표시한다. **사람 손이 꼭 필요한 것만 🖐** 로 둔다.

| 단계 | 누가 판정 | 무엇으로 | 커밋을 막나 |
|---|---|---|---|
| 🤖 자동 | 구현 AI | 테스트 · grep · 파일 검사 (① 체크리스트) | 막는다 — ❌ 면 커밋 안 함 |
| 📷 사진 | **R1** (구현한 세션이 아님) | 작업 세션이 Unity MCP 로 Play → 캡처 · 수치를 `_Verify/<ID>/` 에 남기고 `_Verify/<ID>/검증표.md` 에 항목별 「기대 · 측정값 · 캡처 파일」 을 적는다. R1 이 이미지를 직접 보고 판정 | 막는다 — R1 통과 전 커밋 안 함 |
| 🖐 손맛 | 사람 | 직접 플레이 (반응 속도 · 연출 타이밍 · 조작감 · 소리 · 재미 · 밸런스) | **막지 않는다** — `_검증대기함.md` 에 쌓고 PC 에서 모아 본다 |

흐름:
