## 세계관 · 톤

궤도 화물 정거장의 격리 화물칸에서 정체불명의 외계 점액이 새어 나왔다. 플레이어는 **정거장의 마지막 격리 해치를 지키는 청소 · 격리 담당**이다. 점액이 해치를 넘으면 정거장 전체가 오염된다.

- 톤: 진지한 SF가 아니라 "우주에서도 청소는 힘들다"는 가벼운 직장 코미디 — 경쾌한 연출, 위기는 확실하게
- 대비: 깔끔한 흰 · 주황 청소 장비 vs 끈적한 형광 초록 점액
- 세계관은 직접 만든 설정이며, 지원 회사의 IP(이름 · 설정)는 쓰지 않는다
- 스토리 텍스트는 웨이브 배너 한 줄 정도로만 (예: "C-3 화물칸, 변이 점액 반응")

## 코어 루프 · 승패

웨이브 3개를 모두 막으면 승리, 점액이 격리 해치에 닿아 해치 HP가 0이 되면 패배. 소환 · 머지는 웨이브 도중에도 언제든 할 수 있다.

## 유닛 · 머지 규칙

**같은 종류 · 같은 등급 드론 2대를 드래그로 겹치면 결합해서 한 등급 위 드론 1대가 된다.** 최고 3등급.

- 소환: 보급(코인)을 써서 빈 칸에 1등급 드론을 무작위 종류로 투입. 소환 비용은 소환할 때마다 조금씩 오른다
- 머지 불가 조합(종류 · 등급 불일치)은 자리만 서로 바꿈
- 드론은 자기 레인의 가장 가까운 점액을 자동 공격
- 드론은 관절이 없는 떠 있는 기체라 리깅 · 애니메이션 없이 DOTween 호버링 · 반동으로 움직임을 표현

| 드론 | 역할 | 1등급 | 2등급 | 3등급 |
| --- | --- | --- | --- | --- |
| 흡입 드론 | 단일 고속 공격 (점액을 빨아들임) | 기본 흡입 | 흡입 속도 ↑ | 관통 흡입 |
| 플라즈마 소각 드론 | 부채꼴 범위 공격 | 좁은 범위 | 범위 ↑ | 바닥에 남는 잔열 |
| 냉각 분사 드론 | 감속 (점액을 얼림) | 단일 감속 | 감속 강화 | 광역 빙결 |

수치(공격력, 공격 간격, 사거리, 감속률)는 모두 ScriptableObject로 빼서 플레이하며 조정한다.

## 적 · 웨이브

**적 2종, 웨이브 3개.** 마지막 웨이브는 대량 스폰으로 성능 측정 구간을 겸한다. 점액도 관절이 없는 덩어리라 DOTween 스쿼시 · 스트레치로 출렁이며 다가온다.

| 오염체 | 속도 | 체력 | 특징 |
| --- | --- | --- | --- |
| 점액 덩어리 | 빠름 | 낮음 | 떼로 몰려옴 |
| 변이 점액 | 느림 | 높음 | 웨이브 후반 등장, 해치 피해 큼 |

| 웨이브 | 구성 | 의도 |
| --- | --- | --- |
| 1 | 점액 덩어리 위주, 적은 수 | 소환 · 머지 조작 익히기 |
| 2 | 점액 덩어리 + 변이 점액 소수 | 소각 · 냉각 드론의 역할 체감 |
| 3 | 점액 덩어리 대량 + 변이 점액 | 머지 판단 압박, 대량 유닛 성능 측정 |

정확한 마리 수와 스폰 간격은 웨이브 데이터(ScriptableObject)에서 조정한다. 3웨이브는 Profiler 측정을 위해 동시 존재 적이 수십 마리가 되도록 잡는다.

## 차별점: 오염 칸 (선택 기능)

**머지가 단순 강화가 아니라 청소 수단이 된다.** 테마(우주 청소)와 시스템(머지)을 한 규칙으로 묶는다.

1. 점액이 격리 해치에 닿으면 해치 HP가 깎이고, 그 레인의 배치 칸 하나가 **점액으로 오염**된다
2. 오염 칸의 드론은 점액에 엉겨 5초간 공격을 멈춘다
3. 오염 칸 위에서 머지하면 결합 순간의 충격으로 즉시 **청소**되고, 청소 보너스로 코인을 조금 받는다
4. 5초가 지나면 점액이 말라 자연 청소

6일차에 품질 기준을 모두 통과했을 때만 넣는다. 없어도 프로토타입은 완결된다.

## 화면 구성

&#91;embedded content: 화면 구성 와이어프레임 · PC 16:9 가로, 고정 쿼터뷰\]

카메라는 해치 뒤쪽 위에서 비스듬히 내려다보는 고정 쿼터뷰다. 레인 5개가 점액의 이동 경로이자 드론의 공격 범위라서, 어느 레인에 어떤 드론을 둘지가 머지와 함께 판단 포인트가 된다. 마우스로 드론을 집으면 바닥 위로 떠오르고, 놓을 칸이 결과에 따라 색으로 표시된다(초록 = 머지 가능). 소환 비용 30은 예시 값이다.

## DOTween 연출

**연출 6종 + 선택 2종. 리깅 없는 3D 모델의 움직임까지 DOTween으로 만든다.** 각 연출은 GIF 한 컷으로 포폴에 들어간다.

| 순간 | 연출 | DOTween 포인트 | 성능 포인트 |
| --- | --- | --- | --- |
| 대기 | 드론은 위아래 호버링, 점액은 출렁이며 이동 | Loop Yoyo, 스쿼시 · 스트레치 Scale | 수십 개 트윈을 재사용, 풀 반납 시 Kill |
| 머지 | 두 드론이 끌려와 결합하고 펑 커지며 등급 색이 바뀜 | Sequence (Move + Scale + Punch + Color) | 이펙트 풀링 |
| 처치 | 데미지 숫자가 튀어 오르고, 점액은 납작해지며 흩어짐 | Jump + Fade, Ease 분기 | 월드 공간 텍스트 풀링, 할당 0 |
| 보급 | 코인이 날아가 HUD 카운터에 꽂히고 숫자가 굴러감 | 월드 → 화면 좌표 이동 + DOCounter | 값이 바뀔 때만 갱신 |
| 웨이브 시작 | 경고 홀로그램 배너, 해치 경고등 점멸 | Sequence 재사용 | SetAutoKill(false) + Restart |
| 피격 | 점액 히트 플래시, 해치 피격 시 카메라 흔들림 | Material Color 깜빡임, DOShakePosition | MaterialPropertyBlock으로 재질 복제 방지 |
| 오염 (선택) | 바닥에 점액 웅덩이가 번짐 | Scale + Fade | — |
| 청소 (선택) | 결합 충격파 링이 퍼지며 웅덩이가 사라짐 | Scale + Fade 링 | 링 풀링 |

## 아트 방향 · 에셋

**무료 3D 로우폴리 우주 에셋을 가져와 재질 · 색 · 크기를 테마에 맞게 고쳐 쓴다. 관절이 있는 캐릭터는 쓰지 않는다.** 이 수정 과정이 공고 우대사항 "에셋 활용 · 수정"의 근거가 된다.

| 요소 | 방향 | 수정 계획 |
| --- | --- | --- |
| 드론 | 흰 기체 + 종류별 포인트 색 (흡입 청록 · 소각 주황 · 냉각 하늘) | 재질 교체, 등급별 부품 추가 · 크기 차이, 발광 링 |
| 점액 | 반투명 형광 초록 덩어리 | 구 · 캡슐 기본 메시에 발광 재질, 변이 점액은 1.5배 + 진한 색 |
| 무대 | 정거장 화물칸 복도, 격리 해치는 노랑 · 검정 경고 줄무늬 | 모듈 키트 조합, 바닥 그리드 라인 발광 |
| 조명 | 어두운 실내 + 점액 발광 + 경고등 | URP 포스트 프로세싱(블룸) |
| UI | 청소 회사 업무용 홀로그램 단말 느낌, 굵은 숫자 | 버튼 · 패널 9-slice 재구성 |

드론 · 점액 모델은 아트 제작 세션이 VARCO 3D로 생성하고, 무대 모듈은 Kenney Space Kit 등 상업 이용 가능한 무료 3D 에셋을 고쳐 쓴다. 사용한 에셋과 라이선스는 README에 정리하고, 원본과 수정본을 나란히 캡처해 둔다(포폴 Before/After).

## 기술 설계 포인트

**포폴 3번 슬라이드(웨이브 · 머지 설계)를 실제 코드로 구현하는 것이 목표다.**

| 설계 | 구현 방식 | 연결되는 기존 경험 |
| --- | --- | --- |
| 데이터 분리 | UnitData · WaveData를 ScriptableObject로, 수치는 코드 밖에서 조정 | Symbiont SO + Excel 파이프라인 |
| 대량 스폰 | 점액 · 투사체 · 데미지 숫자 오브젝트 풀, 웨이브 시작 시 프레임 분산 스폰 | Player vs AI 스폰 17.78ms → 1.49ms |
| 유닛 확장 | 공격 방식을 인터페이스(IAttack)로 선언, 종류별 구현체가 담당 | Symbiont 상호작용 핸들러 구조 |
| 로직 · 뷰 분리 | 그리드 · 머지 판정 = 순수 C# 클래스, 3D 모델 · 연출 = 뷰 컴포넌트 | 판정 로직을 에디터 없이 단위 테스트 |
| 3D 렌더링 | 같은 종류는 머티리얼 공유 + GPU 인스턴싱 · SRP Batcher, 피격 색은 MaterialPropertyBlock | 드로우콜 · 배치 수 Before / After |
| 마우스 입력 | 화면 → 바닥 평면 레이캐스트로 칸 판정, 드래그 중 드론을 바닥 위로 띄움 | 3D 공간 입력 처리 |
| HUD 갱신 | 값이 바뀔 때만 이벤트로 갱신, TMP 무할당 포맷 | BuddyRun UI 50B → 0B |

성능 목표: 1080p, 3웨이브(점액 수십 마리 동시) 구간에서 매 프레임 GC 할당 0, 60fps 유지. Profiler 캡처를 Before/After로 남긴다.

| 기획 · 시스템 설계 | 초안 정리, 예외 상황 찾기 | 규칙 · 수치 결정, 최종 승인 |
| 구현 | Claude Code가 작업 지시서 단위로 구현 | 지시서 작성, 코드 리뷰, 구조 결정 (로직 · 뷰 분리, IAttack) |
| 테스트 | 단위 테스트 초안 작성 | 테스트 케이스 선정, 실패 원인 판단 |
| 아트 | VARCO 3D로 드론 · 점액 모델 생성, 재질 · 색 변형 시안 | 테마에 맞는 시안 선택 · 수정 |
| 성능 | Profiler 결과 해석 보조 | 측정 시나리오 설계, 최적화 결정 |

공정: 작업 지시서 → AI 구현 → 내가 플레이로 검증 → 통과 시 커밋. 하루 단위로 지시서와 결과를 기록해 포폴의 "AI 협업 공정" 근거로 쓴다.

**세션 구성 — 아트 제작 세션은 끊기지 않고 계속 돌아간다.** 세션마다 쓰는 MCP를 나눠, 여러 세션이 동시에 일해도 충돌하지 않게 한다.

| 세션 | 역할 | 사용 MCP | 작업 공간 |
| --- | --- | --- | --- |
| 기획 (리드 PM) | 작업 지시서 작성 · 세션 간 전달 | — | 기획서 2종 |
| 클라이언트 개발 | 게임 로직 · UI · 연출 구현 | Unity MCP | Unity 프로젝트 |
| 아트 제작 | 드론 · 점액 · 무대 3D 에셋 생성 · 수정 | **VARCO 3D MCP만** | [VARCO 3D flow](https://3d.varco.ai/flow/shared/65d78990-8bd9-42da-9328-862583de9b80) |

규칙

1. 아트 제작 세션은 **Unity MCP를 절대 쓰지 않는다.** 다른 세션이 Unity MCP를 쓰는 중에도 아트 작업이 멈추지 않게 하기 위해서다
2. 아트 제작은 위 VARCO 3D flow 한 곳에서만 한다
3. 완성된 에셋은 다운로드해 Unity 프로젝트 밖의 전달 폴더에 두고, 가져오기(import)는 클라이언트 개발 세션이 한다
4. 에셋 하나가 끝날 때마다 아트 세션은 파일 이름 · 용도 · 크기를 기획 세션에 보고한다
