## 공통 규칙

**모든 연출은 게임 로직을 건드리지 않고 이벤트를 구독해서만 동작한다.** 아래 규칙은 지시서 5개 모두에 적용된다.

| 항목 | 규칙 |
| --- | --- |
| 환경 | Unity 6 (URP), DOTween, TextMeshPro, PC 1920×1080 기준 (Canvas Scaler Match 0.5) |
| 담당 세션 | 클라이언트 개발 세션 (Unity MCP 사용). 아트 제작 세션은 Unity MCP를 쓰지 않으므로 이 작업에 관여하지 않음 |
| 폴더 | `Assets/_Project/Scripts/UI/Fx/` · `Assets/_Project/Prefabs/UI/Fx/` · `Assets/_Project/Data/UI/` |
| 글꼴 | 제목 · 팝업 숫자 Bagel Fat One / 단말 라벨 · 메시지 Orbit / HUD 숫자 · 영문 Audiowide / 설명문 Pretendard (TMP Fallback으로 한글 채움) |
| 참고 이미지 | 전달 폴더의 `UI연출_1-1 ~ 1-5_*.png` — 위치 · 크기 · 색은 이미지를 기준으로 맞춤 |

**이벤트 (GameEvents 정적 클래스, 없으면 이 이름으로 새로 만든다)**

| 이벤트 | 인자 | 쓰는 지시서 |
| --- | --- | --- |
| OnWavePrepStart | waveIndex, WaveForecast | 01 |
| OnWaveCleared | waveIndex, PayBreakdown | 04 |
| OnGameEnded | GameResult (승패, 해치 HP, 도달 웨이브, 제거 수, 보너스, 많이 뚫린 레인) | 02 |
| OnHatchDamaged / OnMutantSpawned / OnDroneMerged / OnTileContaminated | 상황별 값 (레인 번호 포함) | 03 |
| OnPauseToggled | isPaused | 05 |

**DOTween 규칙**

- 반복해서 쓰는 연출은 Sequence를 한 번 만들어 `SetAutoKill(false)` 후 `Restart()`로 재생한다
- 모든 트윈에 `SetLink(gameObject)`를 걸어 오브젝트가 사라질 때 같이 정리되게 한다
- 게임이 멈춘 상태(timeScale 0)에서 도는 연출(02 · 05)은 `SetUpdate(true)`를 건다
- 텍스트 갱신은 TMP `SetText()` 무할당 포맷만 쓴다. 연출이 끝나고 대기 중인 프레임의 GC 할당은 0이어야 한다
- 화면에 동시에 여러 개가 뜨는 요소(메신저 말풍선, 레인 핑)는 오브젝트 풀로 재사용한다
- 연출 중에도 그리드 입력은 막지 않는다. 예외: 02 결과 화면은 도장이 찍힐 때까지 버튼 입력을 막는다

**선행 작업 · 순서**

| 순서 | 지시서 | 먼저 있어야 하는 것 |
| --- | --- | --- |
| 1 | 공통 | GameEvents, UiFxRoot 캔버스, 글꼴 TMP 에셋 |
| 2 | 05 휴게 시간 | GameManager의 일시정지 처리 |
| 3 | 02 결재 도장 | 결과 패널 프리팹 (시스템 기획서의 결과 패널 구조) |
| 4 | 04 수당 영수증 | 경제 시스템의 보상 내역(PayBreakdown), 코인 표시값 · 실제값 분리 |
| 5 | 01 작업 지시서 | WaveSpawner가 웨이브 시작 전에 스폰 순서를 미리 만드는 구조 (주의 레인 계산용) |
| 6 | 03 관제실 메신저 | 레인 번호 → 월드 위치 변환 (레인 핑용) |

## WO-UI-01 작업 지시서 출력

**목표: 웨이브 준비 시간이 시작될 때 화면 위 슬롯에서 작업 지시서가 출력되고, "접수" 도장이 찍힌 뒤 웨이브 패널로 빨려 들어간다.** 참고 이미지: `UI연출_1-1_작업지시서.png`

| 항목 | 내용 |
| --- | --- |
| 트리거 | OnWavePrepStart (웨이브 1 · 2 · 3 모두) |
| 위치 | 화면 위 가운데, 해치 HP 패널 바로 아래 (앵커 Top Center, Pivot Top) |
| 총 길이 | 1.7초 — 준비 시간(첫 웨이브 8초, 이후 5초) 안에 끝남 |
| 사용 데이터 | WaveForecast: 웨이브 번호, 점액 수, 변이 점액 수, 주의 레인 |
| 선행 작업 | WaveSpawner가 준비 시간 시작 시 시드 기반으로 스폰 순서(레인 포함)를 미리 만들고, 변이 점액이 가장 많이 배정된 레인을 주의 레인으로 넘김 |

**구성**

```
WaveOrderCard (WaveOrderCardView.cs)
├ Slot Image · 발광 라인
└ Paper RectMask2D · 높이 0 → 430
 ├ Header "작업 지시서" (Pretendard Black) · No. C3-W0n (Audiowide)
 ├ Rows 현장 / 작업 / 예상 오염량 / 주의 레인 / 담당 (Orbit, 항목당 TMP 2개)
 ├ Barcode Image
 └ Stamp Image + CanvasGroup · "접수"
```

**연출 시퀀스**

| 시점 | 대상 | 동작 | DOTween |
| --- | --- | --- | --- |
| 0.00 | Slot | 발광 라인 켜짐 | DOFade 0 → 1, 0.15초 |
| 0.10 | Paper | 아래로 출력, 살짝 흔들림 | DOSizeDelta 높이 0 → 430, 0.45초 OutQuad + DOShakeRotation(0.3초, 2°) |
| 0.60 | Stamp | 내려찍기 | Scale 1.6 → 1, 0.18초 InBack + DOFade 0 → 1 |
| 0.78 | Paper · 카메라 | 도장 충격 | DOPunchScale(0.04) + 카메라 흔들림 이벤트(강도 0.1) |
| 1.20 | Paper | 접히며 웨이브 패널로 이동 | Scale 1 → 0.1 + DOMove(웨이브 패널 위치), 0.4초 InQuad |
| 1.60 | 웨이브 패널 | 웨이브 번호 갱신 | DOPunchScale(0.12), 0.2초 |

**규칙 · 예외**

- 지시서를 클릭하면 바로 1.20 구간(흡수)으로 건너뛴다. 지시서 외의 영역은 raycastTarget 끔 — 그리드 조작을 막지 않는다
- 변이 점액이 0마리인 웨이브는 주의 레인 줄에 "없음"을 표시한다
- 도장 각도는 -18° ~ -10° 사이 무작위 — 매번 똑같이 찍히지 않게
- 문구는 WaveOrderText SO에 둔다 (현장 이름, 담당, 작업 이름)

**완료 기준**

- [ ] 웨이브 1 · 2 · 3 시작 때마다 재생되고, 점액 수 · 주의 레인이 WaveData · 스폰 순서와 일치한다
- [ ] 주의 레인이 실제로 변이 점액이 가장 많이 나오는 레인이다
- [ ] 클릭 건너뛰기가 동작하고, 연출 중에도 소환 · 머지가 된다
- [ ] 16:9 · 21:9에서 해치 HP 패널과 겹치지 않는다
- [ ] 두 번째 재생부터 GC 할당 0 (Sequence 재사용)

## WO-UI-02 결재 도장 결과 화면

**목표: 게임이 끝나면 화면이 멈추고 결과 패널이 켜진 뒤, 승리면 "청소 완료", 패배면 "재작업 요청" 도장이 찍힌다.** 참고 이미지: `UI연출_1-2_결재도장_결과.png`

| 항목 | 내용 |
| --- | --- |
| 트리거 | OnGameEnded(GameResult) |
| 위치 | 화면 가운데, 520 × 640 |
| 총 길이 | 1.2초 (이후 버튼 입력 허용) |
| 사용 데이터 | 승패, 남은 해치 HP 또는 도달 웨이브, 제거한 점액, 웨이브 클리어 보너스 또는 많이 뚫린 레인 |
| 선행 작업 | 결과 패널 프리팹 — 시스템 기획서의 결과 패널 구조(프리팹 하나, 색 테두리 칸만 교체)를 따름 |

**구성**

```
ResultScreen (ResultScreenView.cs)
├ Dim Image · 검정 55% (선택: 블러 머티리얼)
└ Panel CanvasGroup · 상태 색 테두리
 ├ Header 제목 (Bagel Fat One) · 부제 (Orbit)
 ├ WaveBar 칸 3개
 ├ StatCard × 2 첫 칸만 결과에 따라 라벨 교체
 ├ InfoRow 보너스 ↔ 많이 뚫린 레인
 ├ Buttons 다시 하기 (R) · 타이틀로 (Esc)
 └ Stamp Image + CanvasGroup · StampData
```

**연출 시퀀스 (전부 SetUpdate(true))**

| 시점 | 대상 | 동작 | DOTween |
| --- | --- | --- | --- |
| 0.00 | GameManager · Dim | timeScale 0, 배경 어둡게 | Dim DOFade 0 → 0.55, 0.25초 |
| 0.30 | Panel | 스캔라인 부팅 후 켜짐 | Scale 0.96 → 1 + DOFade, 0.2초 · 스캔라인 머티리얼 _Progress 0 → 1 |
| 0.40 | StatCard · InfoRow | 숫자가 0부터 올라감 | DOCounter, 0.5초 |
| 0.90 | Stamp | 내려찍기 | Scale 1.8 → 1, 0.2초 InBack + DOFade |
| 1.10 | Panel | 도장 충격 | DOPunchScale(0.03) |
| 1.20 | Buttons | 입력 허용 | interactable = true |

**규칙 · 예외**

- StampData SO 2개: 승리 "청소 완료" (부제 "결재 · C-3 관제실"), 패배 "재작업 요청". 둘 다 주홍 잉크, 각도 -14° ~ -8° 무작위
- 도장이 찍히기 전(1.2초 전) 클릭하면 연출을 끝 상태로 건너뛴다 (버튼이 바로 눌리진 않음)
- 다시 하기 · 타이틀로를 누르면 반드시 timeScale을 1로 되돌린 뒤 씬을 바꾼다
- 시스템 기획서 예외 규칙대로 마지막 점액 제거와 HP 0이 같은 프레임이면 패배 화면을 띄운다
- 드래그 중에 게임이 끝나면 드래그를 취소한 뒤 연출을 시작한다

**완료 기준**

- [ ] 승리 · 패배 두 경우 모두 참고 이미지와 같은 배치 · 색으로 나온다
- [ ] timeScale 0 상태에서도 모든 연출이 재생된다
- [ ] 1.2초 전에는 버튼이 눌리지 않고, R · Esc 단축키가 동작한다
- [ ] 다시 하기 후 게임이 정상 속도로 진행된다
- [ ] 동시 발생(마지막 제거 + HP 0) 테스트에서 패배가 뜬다

## WO-UI-03 관제실 메신저

**목표: 중요한 순간마다 화면 왼쪽 아래 사내 메신저에 관제실 대사 한 줄이 뜨고, 대사에 나온 레인 바닥에 위치 핑이 찍힌다.** 참고 이미지: `UI연출_1-3_관제실메신저.png`

| 항목 | 내용 |
| --- | --- |
| 트리거 | 아래 대사 표의 이벤트 5종 |
| 위치 | 화면 왼쪽 아래, 드론 범례 패널 바로 위 (앵커 Bottom Left), 470 × 300 |
| 총 길이 | 말풍선 1개당 4초 표시 후 접힘 |
| 사용 데이터 | OpsLineTable SO (트리거, 우선순위, 대사 목록, 레인 핑 여부) |
| 선행 작업 | 레인 번호 → 월드 위치 변환 함수 (그리드 · 레인 설정에서) |

**대사 표 (초안, `{lane}`은 레인 번호)**

| 트리거 | 우선순위 | 대사 예시 | 레인 핑 |
| --- | --- | --- | --- |
| 해치 HP 5 이하 (최초 1회) | 1 | "해치 얼마 안 남았어요! 퇴근은 해야죠!!" | — |
| 변이 점액 등장 | 2 | "{lane}레인 또 샜어요!! 변이 점액이에요. 냉각 드론 붙여 주세요" | 해당 레인 |
| 해치 피격 | 3 | "{lane}레인에서 뚫렸어요. 청소비 누가 내요…" | 해당 레인 |
| 칸 오염 | 4 | "드론이 점액에 묻었어요. 같은 드론으로 결합하면 씻겨져요!" | 해당 레인 |
| 3등급 결합 (최초 1회) | 5 | "오, 상위 모델 승인됐습니다. 예산 팀이 울겠네요" | — |

**구성**

```
OpsMessenger (OpsMessengerView.cs)
├ Header 초록 점 "관제실 채널 · 업무 중" · 플레이 시간
├ BubblePool 말풍선 3개 (아바타 · 이름 · 본문)
└ TypingRow "○○ 입력 중 ●●●"
LanePing (LanePingPool.cs, 월드 공간) 링 3개
```

**연출 시퀀스**

| 시점 | 대상 | 동작 | DOTween |
| --- | --- | --- | --- |
| 0.00 | TypingRow | "입력 중…" 표시, 점 3개 깜빡임 | 점마다 DOFade 루프, 0.1초씩 어긋남 |
| 0.50 | 이전 말풍선 | 위로 밀리며 흐려짐 | DOAnchorPosY +84 + DOFade 1 → 0.45, 0.2초 |
| 0.50 | 새 말풍선 | 팝 | Scale 0.6 → 1, 0.25초 OutBack |
| 0.50 | LanePing | 레인 끝에 링이 퍼짐 | 링 3개 Scale 0.5 → 2 + DOFade 1 → 0, 1초 × 2회 |
| 4.50 | 가장 오래된 말풍선 | 접힘 | DOFade 0 + 높이 0, 0.25초 → 풀 반납 |

**규칙 · 예외**

- 전체 쿨다운 8초. 쿨다운 중에 우선순위가 더 높은 트리거가 오면 바로 띄운다 (1이 가장 높음)
- 화면에는 말풍선을 최대 2개만 둔다
- 같은 트리거의 대사는 목록에서 순서대로 돌려 같은 말이 연속으로 나오지 않게 한다
- `{lane}` 치환으로 메시지당 문자열 1회 할당은 허용한다. 대기 프레임의 할당은 0
- 휴게 시간 · 결과 화면 중에는 새 메시지를 띄우지 않는다

**완료 기준**

- [ ] 트리거 5종이 모두 동작하고, 쿨다운 · 우선순위가 표대로 적용된다
- [ ] 레인 핑이 대사에 나온 레인 위치에 정확히 찍힌다
- [ ] 드론 범례 패널 · 그리드를 가리지 않는다 (16:9 · 21:9)
- [ ] 말풍선 · 링을 풀에서 재사용한다 (Instantiate 0회)
- [ ] 대사를 SO만 고쳐서 바꿀 수 있다

## WO-UI-04 수당 영수증

**목표: 웨이브를 막으면 코인 패널 아래로 수당 명세가 출력되고, 항목이 한 줄씩 찍힌 뒤 말려 올라가 코인에 합산된다.** 참고 이미지: `UI연출_1-4_수당영수증.png`

| 항목 | 내용 |
| --- | --- |
| 트리거 | OnWaveCleared(waveIndex, PayBreakdown) — 웨이브 1 · 2만. 마지막 웨이브는 결과 화면(02)이 보너스를 보여 주므로 띄우지 않음 |
| 위치 | 코인 패널 바로 아래 (앵커 Top Right, Pivot Top), 폭 208 · 높이 최대 430 |
| 동시 연출 | 화면 위 "웨이브 N 클리어!" 배너 (Bagel Fat One) |
| 총 길이 | 2.0초 — 다음 준비 시간(5초) 안에서 끝나고, 끝나면 01 작업 지시서가 이어짐 |

**규칙 · 예외**

- 연출 중에 코인을 쓰면(소환) 마지막 DOCounter의 목표는 그 시점의 실제값으로 다시 잡는다

## WO-UI-05 휴게 시간

**목표: Esc 또는 일시정지 버튼을 누르면 게임이 멈추고, 커피잔이 달린 "휴게 시간" 카드가 뜬다.** 참고 이미지: `UI연출_1-5_휴게시간.png`

| 항목 | 내용 |
| --- | --- |
| 트리거 | Esc · HUD 일시정지 버튼 · 창이 포커스를 잃음(Alt+Tab, OnApplicationFocus false) |
| 위치 | 화면 가운데, 560 × 560 |
| 버튼 | 업무 복귀(= 계속하기, Esc) · 처음부터 다시(= 다시 하기) · 퇴근하기(= 타이틀로) |
| 표시 정보 | 근무 시간(일시정지를 뺀 플레이 시간), 현재 웨이브, 해치 HP, 팁 1줄 |
| 선행 작업 | GameManager의 일시정지 상태 · OnPauseToggled 이벤트 |

**구성**

```
BreakTimePanel (BreakTimeView.cs)
├ Dim Image · 검정 60%, 채도 낮춤 (선택: 블러)
└ Card CanvasGroup
 ├ Cup 커피잔 Image + 김 3줄 (Image 또는 UI 파티클)
 ├ Title "휴게 시간" (Bagel Fat One)
 ├ Status 근무 시간 · 웨이브 · 해치 (Orbit + Audiowide)
 ├ Buttons 업무 복귀 · 처음부터 다시 · 퇴근하기
 └ Tip TipTable SO에서 1줄
```

**연출 시퀀스 (전부 SetUpdate(true))**

| 시점 | 대상 | 동작 | DOTween |
| --- | --- | --- | --- |
| 0.00 | GameManager | timeScale 0, 게임 효과음 일시정지 (UI 효과음은 재생) | — |
| 0.00 | Dim | 어둡게 | DOFade 0 → 0.6, 0.2초 |
| 0.05 | Card | 등장 | Scale 0.9 → 1 OutBack + DOFade, 0.25초 |
| 루프 | Cup 김 | 위로 피어오르다 흐려짐 | DOLocalMoveY +12 + DOFade, 1.2초 Yoyo 루프, 3줄이 0.3초씩 어긋남 |
| 루프 | Tip | 6초마다 다음 팁 | DOVirtual.DelayedCall(6, …).SetUpdate(true) + 크로스페이드 0.2초 |
| 복귀 | Card · Dim | 사라짐 후 재개 | 거꾸로 0.15초 → 끝난 뒤 timeScale 1 |

**규칙 · 예외**

- 결과 화면(02)이 떠 있을 때는 열리지 않는다
- 열리는 순간 드래그 중인 드론은 원래 칸으로 돌려보낸다 (시스템 기획서 Alt+Tab 예외와 같은 규칙)
- 열려 있는 동안 그리드 · 소환 입력과 Space 단축키는 막는다
- 연출 중인 다른 UI(01 · 03 · 04)는 timeScale을 따르므로 함께 멈추고, 복귀하면 이어서 재생된다
- 다시 하기 · 타이틀로는 timeScale을 1로 되돌린 뒤 씬을 바꾼다

**완료 기준**

- [ ] Esc · 버튼 · Alt+Tab 세 경로 모두로 열리고, Esc로 닫힌다
- [ ] timeScale 0에서도 카드 · 김 · 팁 연출이 돈다
- [ ] 열려 있는 동안 점액 · 드론 · 웨이브 타이머가 완전히 멈추고, 복귀 후 이어서 진행된다
- [ ] 근무 시간에 일시정지 시간이 더해지지 않는다
- [ ] 열려 있는 동안 그리드를 클릭해도 아무 일도 일어나지 않는다
