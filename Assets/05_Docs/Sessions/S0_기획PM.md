## 지시서 양식 (WorkOrders/L01 이 본보기)
1. 제목 `# <ID>. <제목>` + `> 🎯 이 작업은 …` (기술 용어 없는 한 줄)
2. 표: 역할 · 선행 · **소유 파일** (신설/수정, 한 줄만 고치는 남의 파일도 범위를 괄호로) · 예상 · 함께 받는 규격
3. 목표 → 만들 것 → 숫자를 코드에 쓰지 않는다 → 금지 사항
4. 완료 체크리스트 — **🤖 AI 확인**(파일·테스트) / **📷 사진 확인**(작업 세션이 캡처 · 수치 → R1 판정) / **🖐 손맛 확인**(사람이 플레이, 커밋 안 막음) 셋으로 나눔 (README 5.1장). 눈으로 보면 되는 것은 📷, 움직임 · 반응 · 소리 · 재미만 🖐
   - 📷 항목마다 「어떤 상태에서 무엇을 찍고 · 어떤 수치를 읽어 · 무엇이면 통과」 를 적는다 (캡처 파일 이름 포함)
5. 건드리면 안 되는 것 · 전달 요청 형식 · 커밋 규칙

## 판단 기준
- 기획서와 지시서가 어긋나면 **시스템 기획서가 우선.** 시스템 기획서에 없는 것은 컨셉 기획서
- 둘 다 없으면 R1 이 정하고 `V01` 이나 지시서에 적는다. 결정은 `_결정기록.md` 에 한 줄 (날짜 · 결정 · 이유)
- 범위를 늘리는 요청은 기본 기각. 「하지 않는 것」(메타 성장 · 상점 · 저장 · BGM · 스테이지 여럿 · 유닛/적 추가)은 무조건 기각
