## 3. 좌표 · 거리 (R1 결정 · 2026-11-10 개정 — 레퍼런스 화면 `Reference/ingame_reference.png` 기준)

**격리선(= 격리 해치)이 드론 칸과 점액 경로 사이에 있다.** 점액은 격리선에서 막히고 드론 칸에 들어오지 않는다.
```
       z (먼 쪽, 화물칸)
       ▲
  10 ─ ┼ 스폰선  ← 점액이 나오는 곳 (pathLength = 10)
       │   점액은 -z 로 직진, 레인 안 바꿈
       │
   0 ─ ┼━━━━━━━━━━━━━━━ 격리선 · 격리 해치 (z = 0) ← 점액이 닿으면 해치 피해
  -1 ─ ┤ row 0 ┐
  -2 ─ ┤ row 1 ├ 배치 칸 3줄 (rowCount = 3), 격리선 뒤 = 카메라 쪽
  -3 ─ ┤ row 2 ┘
       └──┬──┬──┬──┬──┬──► x
         l0 l1 l2 l3 l4    (laneCount = 5)
       카메라 (row 2 뒤 위)
```
| 대상 | 공식 (칸 단위, 월드 = 칸 × `GameConfig.cellSize`) |
|---|---|
| 칸 `(lane, row)` 중심 | `x = (lane - (laneCount-1)/2f)`, `z = -(row + 1)` |
| 점액 위치 | `(lane, dist)` — `dist` = 격리선까지 남은 칸 (`z = dist`). 스폰 시 `pathLength`, `dist ≤ 0` 이면 격리선 도달 |
| 드론 사거리 | **격리선부터** 먼 쪽으로 `range` 칸. 점액 `dist ∈ [0, range]` 면 사거리 안. **드론이 어느 줄에 있든 같다** |
| 타겟 우선 | 사거리 안에서 `dist` 가 가장 작은 점액 (격리선에 가장 가까운) |
| 칸 인덱스 | `index = row * laneCount + lane` (0~14) |

- 줄(row)은 배치 공간일 뿐 전투 차이가 없다. 판단은 **어느 레인에 무엇을 두나** (컨셉 기획서 「화면 구성」)
- 시스템 기획서 「유닛 전투」의 "사거리는 드론 칸부터 먼 쪽으로" 는 이 표로 대체한다 (`_결정기록.md` 2026-11-10)

- 판정(Core)은 전부 **칸 단위 float** 로 한다. 월드 좌표 변환은 Game 의 `GridSpace` 한 곳에서만
- 마우스 → 칸: 카메라 레이를 `y = 0` 평면과 교차 → `GridSpace.WorldToCell`. Collider 레이캐스트 쓰지 않는다

## 4. 데이터 — ScriptableObject 5종 (수치 4종 + 입구 `GameDataSet`, 코드에 수치 금지)

| SO | 필드 (시스템 기획서 「데이터 구조」 + R1 추가) |
|---|---|
| `UnitData` | `droneType` · `grade` · `damage` · `attackInterval` · `range` · `attackKind` · `slowRate` · `slowDuration` · `pierceCount` · `coneLaneSpread` · `burnDps` · `burnDuration` · `freezeInterval` · `freezeRadius` · `freezeDuration` · `prefab` · `tintColor` |
| `EnemyData` | `slimeType` · `maxHp` · `moveSpeed` · `hatchDamage` · `reward` · `prefab` · `scale` |
| `WaveData` | `waves[] { entries[] { slime, count, spawnInterval, startRatio }, prepTime, clearBonus, bannerText }` |
| `GameConfig` | `laneCount` · `rowCount` · `pathLength` · `cellSize` · `hatchMaxHp` · `hatchCriticalHp` · `startCoin` · `summonBaseCost` · `summonCostStep` · `mergeLockDuration` · `contaminateDuration` · `cleanReward` · `randomSeed` |

- 입구 SO `GameDataSet` 하나가 위 4종을 전부 참조한다. Bootstrap 은 이것 하나만 직렬화 필드로 받는다 (`Resources.Load` 안 씀 — `04_Resources` 는 Unity `Resources` 폴더가 아니다)
- 시스템 기획서 표의 「특수」 열을 필드로 풀었다. `pierceCount` = 한 번에 맞히는 마리 수(기본 1), `coneLaneSpread` = 양옆 레인 수(자기 레인만 0). 그 밖에 해당 없으면 0
- 에셋 수치는 R2 소유. 예외: `prefab` 칸은 R3, `tintColor` 칸은 R4 가 그 칸만 고친다
- 머지 결과는 `(droneType, grade+1)` 로 `UnitCatalog` 에서 찾는다 — 머지 테이블 없음
- Core 는 SO 를 모른다. Data 가 SO → Core 의 불변 구조체(`UnitStats` · `SlimeStats` · `WaveSpec` · `RuleConfig`)로 바꿔 넘긴다

## 5. 이벤트 (Game 의 `GameEvents` — R3 소유)

시스템끼리 직접 참조하지 않는다. UI · FX · Audio 는 **구독만** 한다. 값이 바뀔 때만 발행한다.

| 이벤트 | 인자 | 발행 |
|---|---|---|
| `CoinChanged` | `int now, int delta` | 소환 · 처치 · 웨이브 보너스 |
| `SummonCostChanged` | `int cost` | 소환 직후 |
| `SummonAvailabilityChanged` | `SummonBlock reason` (None · NoCoin · NoCell) | 코인 · 칸 변화 |
| `DroneSpawned` | `int cell, DroneType, int grade` | 소환 |
| `DroneMerged` | `int fromCell, int toCell, DroneType, int newGrade` | 머지 |
| `DroneMoved` / `DroneSwapped` | `int a, int b` | 드롭 |
| `SlimeSpawned` / `SlimeKilled` / `SlimeReachedHatch` | `SlimeView` | 웨이브 진행 |
| `SlimeDamaged` | `SlimeView, int damage` | 공격 |
| `RemainingSlimesChanged` | `int` | 스폰 · 처치 · 도달 |
| `HatchHpChanged` | `int now, int max` | 피해 |
| `PrepTick` | `int secondsLeft` | 준비 상태 1초마다 |
| `WaveStarted` | `int index, int total, string banner` | 웨이브 시작 |
| `StateChanged` | `GameState` (Title · Prep · Wave · Paused · Result) | 상태 전환 |
| `GameEnded` | `ResultSummary` (승패 · 남은 HP · 제거 수 · 3등급 수) | 승패 |

- `event Action<…>` 정적 이벤트. 씬 리셋 시 `GameEvents.ClearAll()` 로 구독 해제
- 이벤트 추가는 R3 에 전달 요청

## 6. 성능 규칙 (처음부터 지킨다 — P03 에서 고치는 게 아니라 확인만 하게)

- 점액 · 투사체 · 빔 · 데미지 숫자 · 이펙트 = **오브젝트 풀** (`QL.Game.Pooling.Pool<T>`). `Instantiate`/`Destroy` 는 풀 생성 때만
- `Update` 안에서 `new` · LINQ · 문자열 연결 · 박싱 · `foreach` on `List<interface>` 금지
- 피격 색은 `MaterialPropertyBlock`. `renderer.material` 접근 금지 (재질 복제)
- 같은 종류는 머티리얼 공유 + GPU Instancing, SRP Batcher 켬
- TMP 는 `SetText("{0}", value)` — `ToString()` · 보간 문자열 금지
- 풀에 반납할 때 그 오브젝트의 트윈을 `Kill`

## 7. 시간

- 게임 시간은 `Time.deltaTime`. 일시정지 = `Time.timeScale = 0`
- UI 연출 트윈은 `SetUpdate(true)` (일시정지 화면에서도 움직임)
- Core 는 시간을 스스로 읽지 않는다. `Tick(float dt)` 로 받는다 (테스트 가능하게)

## 8. 난수

- Core 는 `IRandom` 인터페이스만 안다. Game 이 `GameConfig.randomSeed` 로 만든 구현을 주입
- 테스트는 고정 시퀀스 `FakeRandom`
