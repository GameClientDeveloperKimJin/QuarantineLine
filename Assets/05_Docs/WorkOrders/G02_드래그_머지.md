## 목표
L03 `GridModel` · `MergeRule` 의 판정을 **그대로** 화면에 올린다. 뷰는 판정하지 않는다 — 놓기 전 하이라이트 색도 `MergeRule.Resolve` 로 미리 물어서 칠한다.
연출은 자리표시 수준(즉시 이동 · 즉시 색 변경). 머지 펑 · 호버링 · 외곽선은 U03 · U04.

```
Mouse ─► DragController (입력만 읽음) ─► BeginAt / HoverAt / ReleaseAt / Cancel   ← PlayMode 테스트도 이걸 직접 부른다
                                            │
                     GridModel.BeginDrag / MergeRule.Resolve(미리보기) / GridModel.Drop
                                            │ DropResult
                     DroneBoard.Apply(result) ── DroneView 위치 · 등급 갱신
                     CellHighlighter ── 칸 색 (MaterialPropertyBlock)
                     GameEvents.DroneMoved / DroneSwapped / DroneMerged
```

## 만들 것

### 1. `GameEvents.cs` — `V01` 5장 중 지금 쓰는 것만 선언
```csharp
public static class GameEvents
{
    public static event Action<int, int> DroneMoved;                    // from, to
    public static event Action<int, int> DroneSwapped;                  // a, b
    public static event Action<int, int, DroneType, int> DroneMerged;   // from, to, type, newGrade
    public static event Action<int> DragStarted;                        // from  (U03 · U04 용)
    public static event Action<int, DropOutcome> DragEnded;             // from, outcome (취소 = Return)

    internal static void RaiseDroneMoved(int from, int to) => DroneMoved?.Invoke(from, to);
    // … 나머지 Raise 도 같은 꼴
    public static void ClearAll();   // 모든 이벤트 null
}
```
- `V01` 5장의 나머지(코인 · 점액 · 웨이브)는 **그 작업(G03~G06)이 추가**한다. 미리 선언하지 않는다
- 발행은 `QL.Game` 안에서만 (`internal Raise…`). UI · FX 는 구독만
- `GameBootstrap.OnDestroy` 에서 `ClearAll()` (씬 재시작 대비)

### 2. `Drones/DroneView.cs` · `Drone_Placeholder.prefab`
- 자리표시 프리팹: 납작한 Capsule 또는 Sphere 하나 + `Mat_Drone`(흰색, URP Lit, **GPU Instancing 켬**). Collider 없음. **이 프리팹을 `Unit_*.asset` 9개의 `prefab` 칸에 넣는다** (아트 모델은 G07 에서 교체)
- `DroneView` (프리팹 루트에 붙음):
  - `Show(DroneType type, int grade, Color tint)` — 색은 **`MaterialPropertyBlock` 의 `_BaseColor`** 로 (`renderer.material` 금지)
  - 등급 크기 차이: `[SerializeField] float[] gradeScale` (기본 `1, 1.15, 1.3`) — 연출값. 배열 길이 < 등급이면 마지막 값
  - 바닥에서 띄우는 높이 `[SerializeField] float hoverHeight` (기본 0.35칸) — 떠 있는 기체 (호버링 애니메이션은 U04)
  - `SetLifted(bool)` — 집으면 `liftHeight`(기본 0.8칸)로 올림 / 내려놓으면 `hoverHeight`
- `UnitData.TintColor` 는 `GameDataSet` 에서 `(type, grade)` 로 찾는다 (`Catalog` 는 Core 라 색이 없다)

### 3. `Drones/DroneBoard.cs` — 칸 인덱스 ↔ `DroneView`
- `DroneView[] views` (길이 `CellCount`). 뷰는 **풀**에서 꺼내고 반납 (`CellCount` 개 미리 생성, 런타임 `Instantiate` 없음)
- `SyncCell(int index)` — `Grid.Get(index)` 를 읽어 뷰를 맞춤 (있으면 Show, 없으면 반납)
- `SyncAll()` — 전체
- `Apply(in DropResult r)` — Outcome 별:
  | Outcome | 뷰 |
  |---|---|
  | `Move` | from 뷰를 to 로 옮김 (views 배열 교환) |
  | `Swap` | 두 뷰 위치 교환 |
  | `Merge` · `MergeClean` | from 뷰 반납, to 뷰를 새 등급으로 `Show` |
  | `Reject` · `Return` | from 뷰를 원래 칸 위치로 내려놓음 |
  끝나면 관련 칸 `SyncCell` 로 Core 상태와 한 번 더 맞춘다 (뷰가 Core 와 어긋나지 않게)
- `ViewAt(int index)` · `TryGetDragged(out DroneView)`

### 4. `Input/CellHighlighter.cs` — 칸 색
- `G01` 의 `StageBuilder.CellRenderers` 에 `MaterialPropertyBlock` 으로 색을 칠한다. **칸마다 MPB 공유 1개 재사용**
- 직렬화 색 필드 (연출값, U03 이 다듬음): `normal` · `move`(흰) · `merge`(초록) · `swap`(노랑) · `reject`(빨강) · `origin`(집은 칸, 반투명 느낌의 어두운 색) · `hover`(드론 위 마우스, 살짝 밝게)
- `Set(int index, DropOutcome? preview)` / `SetOrigin(int)` / `SetHover(int)` / `Clear()`
- 같은 색을 다시 칠하지 않는다 (바뀐 칸만 갱신)

### 5. `Input/DragController.cs` — 입력 → 흐름
**입력 읽기 (Input System, `Mouse.current`)** 와 **흐름 메서드**를 나눈다. 흐름 메서드는 public — PlayMode 테스트가 마우스 없이 부른다.
| 흐름 메서드 | 하는 일 |
|---|---|
| `bool BeginAt(int cell)` | `Grid.BeginDrag(cell)` 성공 시 뷰 들어 올림 · 원래 칸 `origin` 색 · `DragStarted` |
| `void HoverAt(int cell, Vector3 floorPoint)` | 드래그 중이면 뷰를 `floorPoint` 위 `liftHeight` 로 · `MergeRule.Resolve(from, cell)` 결과로 그 칸 색 (`cell == -1` 이면 색 없음) / 드래그 중 아니면 드론 칸에 `hover` |
| `DropResult ReleaseAt(int cell)` | `Grid.Drop(cell)` → `DroneBoard.Apply` → 결과별 `GameEvents` → 색 정리 · `DragEnded` |
| `void Cancel()` | `Grid.CancelDrag()` → 뷰 원위치 → 색 정리 · `DragEnded(from, Return)`. 드래그 중 아니면 아무 일 없음 |

**입력 → 흐름 연결 (`Update`)**
1. `Camera.main` 대신 직렬화 참조 카메라 → `ScreenPointToRay(mouse.position)` → `Space.TryRaycastFloor` → `Space.WorldToCell` (실패 = -1)
2. 왼쪽 버튼 `wasPressedThisFrame` → `BeginAt(cell)`
3. 매 프레임 `HoverAt(cell, point)`
4. 왼쪽 버튼 `wasReleasedThisFrame` (드래그 중) → `ReleaseAt(cell)`
5. 오른쪽 버튼 `wasPressedThisFrame` 또는 `Keyboard.current.escapeKey.wasPressedThisFrame` → `Cancel()`
6. `OnApplicationFocus(false)` → `Cancel()` (Alt+Tab — 시스템 기획서 예외 표)
- `Update` 할당 0 · `Camera.main` 매 프레임 호출 금지
- Esc 는 나중에 일시정지(G06)와 겹친다 — **드래그 중이면 드래그 취소가 우선**이라는 것만 지키면 된다 (G06 이 이어받음)

### 6. `Drones/DroneSeeder.cs` — 테스트 · 확인용 시작 배치

### ★ 사람이 확인한다
1. `Game.unity` 를 Play 한다. 바닥 칸 위에 흰 드론 8대가 종류별 색으로 떠 있고, 첫 줄 칸이 그림자에 가려지지 않으면 통과다.
2. 흡입(청록) 드론 하나를 마우스 왼쪽 버튼으로 눌러 끌어 본다. 드론이 들려 커서를 따라오고, 원래 칸이 어둡게 표시되고, 다른 흡입 1등급 칸 위에서는 초록, 빈 칸 위에서는 흰색, 다른 종류 위에서는 노란색으로 칸이 바뀌면 통과다.
3. 같은 흡입 1등급 위에 놓는다. 하나로 합쳐지며 크기가 커지고 색이 2등급 색으로 바뀌면 통과다. 남은 흡입 둘도 합쳐 2등급 둘을 만든 뒤 다시 합쳐 3등급까지 만들어 본다.
4. 3등급 드론을 다른 종류 드론 위에 놓으면 자리가 바뀌고, 무대 밖에 놓거나 끌다가 오른쪽 버튼 · Esc 를 누르면 원래 칸으로 돌아가면 통과다.
5. 손맛 메모: 드래그가 커서를 늦게 따라오거나 칸 판정이 엇나가는 느낌이 있으면 어디서 그랬는지 적어 둔다. (U03 · U04 연출 때 반영)
