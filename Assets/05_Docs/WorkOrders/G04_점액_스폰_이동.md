## 목표
L05 시간표 · L06 `SlimeCombat` 을 화면에 올린다. **판정 · 시간 계산은 Core**, 이 작업은 위치를 옮기고 풀을 관리하고 이벤트를 낸다.

```
TempHud [Wave 1/2/3 (debug)] ─► WaveRunner.StartWave(i)          ← G06 이 GameFlow.WaveStarted 에 연결
                                   │ WaveSchedule.Build → SpawnCursor
WaveRunner.Advance(dt):  cursor.Advance(dt) → 프레임당 최대 spawnPerFrame 마리 TryNext → SlimeRegistry.Spawn
SlimeRegistry.Advance(dt): 살아 있는 점액마다
        combat.Tick(dt) ── 잔열로 죽음 → Despawn(Killed)
        dist -= moveSpeed × combat.SpeedMultiplier × dt
        dist <= 0 ── Despawn(ReachedLine)            ← 해치 피해는 G06 이 GameFlow 에 연결
        위치 = GridSpace.PathToWorld(lane, dist)
        SlimeTarget 스냅샷 배열 갱신 (G05 가 TargetRule 에 넘긴다)
```
**GameFlow(L07) 연결은 G06 이다.** 이 작업에서는 웨이브를 디버그 버튼으로 시작하고, 격리선에 닿은 점액은 이벤트만 내고 사라진다 (해치 HP 는 아직 안 깎임).

## 만들 것

### 1. `Pooling/Pool.cs` — `QL.Game.Pooling`
```csharp
public sealed class Pool<T> where T : Component
{
    public Pool(T prefab, Transform parent, int prewarm);   // 생성자에서 prewarm 개 Instantiate, 비활성
    public T Get();                                           // 남은 게 없으면 1개 더 만들고 경고 로그 1회 (런타임 확장 = 크기 부족 신호)
    public void Release(T item);                              // transform.DOKill() 후 비활성 (V01 6장)
    public int CountActive { get; }
    public int CountTotal { get; }
}
```
- 점액 외에 G05(빔 · 투사체) · U05(데미지 숫자) 가 같은 클래스를 쓴다

### 2. `Slimes/SlimeView.cs` — 점액 하나 (풀 대상, 프리팹 루트)
- 필드: `int Id`(풀 슬롯 번호, 고정) · `SlimeType Type` · `int Lane` · `float Dist` · `SlimeCombat Combat`(**생성 때 1번만 new**, 꺼낼 때 `Reset(maxHp)`) · `int HatchDamage` · `int Reward`
- `Setup(in SlimeStats stats, EnemyData visual, int lane, float dist)` — 크기 = `EnemyData.Scale`, 색은 머티리얼 공유(변이 점액 진한 색은 MPB `_BaseColor` 로)
- 연출(출렁임 · 피격 플래시)은 U04 · U06. 지금은 위치만

### 3. `Slimes/SlimeRegistry.cs` — 살아 있는 점액 목록 · 이동 · 스냅샷
| 멤버 | 하는 일 |
|---|---|
| `SlimeView Spawn(SlimeType type, int lane)` | 풀에서 꺼내 `dist = Config.PathLength` 로 배치 → `SlimeSpawned` |
| `void Despawn(SlimeView s, DespawnReason reason)` | `Killed` → `SlimeKilled` / `ReachedLine` → `SlimeReachedHatch`. 둘 다 `RemainingSlimesChanged`. 풀 반납. **같은 점액을 두 번 반납하지 않는다** (이미 비활성이면 무시) |
| `void Advance(float dt)` | 위 그림 순서. 목록을 도는 중 반납은 **뒤에서 앞으로** 돌거나 반납 목록에 모았다가 처리 (순회 중 컬렉션 변경 금지) |
| `SlimeTarget[] Targets` · `int TargetCount` | 매 Advance 끝에 살아 있는 점액으로 채운 스냅샷 (`Id` = 슬롯). **미리 잡은 배열** — G05 의 `TargetRule` 입력 |
| `bool TryGet(int id, out SlimeView s)` | G05 가 `TargetRule` 결과로 점액을 찾을 때 |
| `int AliveCount` | |
- 풀 크기: 시작 때 모든 웨이브의 `WaveSchedule.Summarize(...).SlimeCount` 중 **최댓값**만큼 미리 만든다 (3웨이브 동시 존재 상한, 수치를 코드에 안 씀)
- `DespawnReason` enum 은 이 파일에 (`Killed`, `ReachedLine`)
- `Update` 에서 `Advance(Time.deltaTime)` — **입력과 흐름 분리 (G02 와 같은 방식)**: 테스트는 `Advance` 를 직접 부른다. `[DefaultExecutionOrder]` 로 `WaveRunner` 다음에 돈다

### 4. `Slimes/WaveRunner.cs`
| 멤버 | 하는 일 |
|---|---|
| `void StartWave(int index)` | `WaveSchedule.Build(spec, Config, Rng)` → `SpawnCursor` 새로 (웨이브 시작 1회 할당 허용) · 남은 점액 = `Summarize().SlimeCount` → `RemainingSlimesChanged` |
| `void Advance(float dt)` | 커서 진행 → 프레임당 최대 `spawnPerFrame`(직렬화, 기본 4) 마리 `Registry.Spawn` — **프레임 분산 스폰** (컨셉 기획서 「대량 스폰」) |
| `bool IsSpawning` · `int RemainingInWave` | 남은 수는 Despawn 이벤트로 깎는다 (G06 에서 `GameFlow.RemainingInWave` 로 바뀐다) |
- 스폰 대기 중 다른 웨이브 `StartWave` 가 오면 이전 커서를 버린다 (디버그 버튼 연타 대비)

### ★ 사람이 확인한다
1. `Game.unity` 를 Play 하고 왼쪽 위 `[Wave 1]` 을 누른다. 화면 위쪽 스폰선에서 초록 점액이 1초쯤 간격으로 무작위 레인에 나와 격리선 쪽으로 다가오고, 격리선에 닿으면 사라지면 통과다.
2. `[Wave 2]` 를 누르고 후반에 나오는 변이 점액을 본다. 일반 점액보다 크고 확실히 느리게 오면 통과다.
3. `[Wave 3]` 을 누른다. 수십 마리가 한꺼번에 몰려와도 화면이 멈칫하거나 점액이 한 번에 뭉텅이로 튀어나오지 않고 고르게 흐르면 통과다.
4. 손맛 메모: 점액 속도가 너무 빠르거나 느려 보이면 어느 웨이브에서 그랬는지 적어 둔다 (밸런스는 1차 플레이 테스트에서 조정).
