## 목표
`V01` 3장 개정을 화면에 반영한다. **바뀌는 건 칸의 z 와 격리선 모양뿐**이다. 점액 경로(`PathToWorld`) · 레인 x · 칸 인덱스는 그대로다.
```
  스폰선 ───────── z = pathLength
   │ 점액 ↓  (레인 띠는 여기만)
 ━━ 격리선 ━━━━━━━ z = 0   낮은 턱 + 주황 레이저
  [ ][ ][ ][ ][ ]  row 0   z = -1
  [ ][ ][ ][ ][ ]  row 1   z = -2
  [ ][ ][ ][ ][ ]  row 2   z = -3
        카메라
```

## 바꿀 것

### 1. `GridSpace.cs`
| 항목 | 지금 | 바꾼 뒤 |
|---|---|---|
| `CellToWorld(lane, row)` 의 z | `(row + 1) * cs` | **`-(row + 1) * cs`** |
| `WorldToCell` 의 row | `RoundToInt(z / cs) - 1` | **`RoundToInt(-z / cs) - 1`** |
| `StageBounds` | z `0 ~ pathLength` | z **`-(rowCount + 0.5) * cs ~ pathLength * cs`** (칸 3줄 뒤 끝까지 포함) |
| `PathToWorld` · x 공식 · 인덱스 | — | **그대로** |
- 클래스 주석의 좌표 설명(「row 0 = 해치 바로 앞」)을 개정 내용으로 고친다
- `CameraRig` 는 `StageBounds` 를 읽어 자동으로 다시 맞춘다 — **`CameraRig.cs` 코드는 고치지 않는다**

### 2. `StageBuilder.cs`
| 오브젝트 | 바뀐 뒤 |
|---|---|
| 바닥 | z 범위 = `StageBounds` 앞뒤로 `floorMarginCells` 여백 (칸 3줄 뒤까지 덮도록) |
| 레인 띠 5 | **z 0 ~ pathLength 만** (점액 길). 칸 영역에는 깔지 않는다 — 칸이 레인을 대신 보여 준다 |
| 칸 15 | `CellToWorld` 를 쓰므로 코드 변경 없이 따라온다 |
| 격리선 턱 (`Hatch` 오브젝트) | **중심 z = 0** (지금은 해치 뒤에 붙어 있음), 높이 `hatchHeightCells` 씬 값 **0.25**, 두께 `hatchDepthCells` 씬 값 **0.2**, 레인 폭 전체, 그림자 Off 유지 |
| 레이저 (`Laser` 신설) | 턱 위 `laserHeightCells`(기본 0.35) 높이에 가로로 긴 얇은 막대, 두께 `laserThicknessCells`(기본 0.03), 레인 폭 전체, `Mat_Laser` (주황 `#FF8A2A`, URP **Unlit**, 그림자 Off) — 블룸은 U07 |
| 스폰선 | 그대로 |
- 새 직렬화 필드 2개 + 재질 참조 1개만 추가. **기존 필드 이름은 바꾸지 않는다** (씬 직렬화가 끊긴다)
- 하이어라키: `[Stage]/Hatch` 이름 유지 + `[Stage]/Laser` 추가
- 노랑 · 검정 줄무늬 · 경고등은 아트(A06) 이후 G07 에서. 지금은 노란 턱으로 둔다

### 3. `Game.unity`
- `StageBuilder`: `hatchHeightCells` 0.25 · `hatchDepthCells` 0.2 · `Mat_Laser` 연결
- `CameraRig`: 코드는 그대로, **pitch 만** 화면을 보고 조정해도 된다 (레퍼런스는 칸이 화면 아래 1/3, 점액 길이 위 2/3). 바꿨으면 값을 보고에 적는다

### 4. `GridSpaceTests.cs` — 개정 좌표로
- `CellToWorld_RowZero_IsOneCellFromHatch` → **`CellToWorld_RowZero_IsOneCellBehindLine`** (z = −cs)
- `WorldToCell_OutsideGrid_ReturnsMinusOne` — 경우를 개정: 격리선 앞(z > 0, 점액 길 위) · 마지막 줄 뒤 · 레인 밖
- 신설 `StageBounds_ContainsAllCellsAndSpawnLine` — 모든 칸 중심과 스폰선이 `StageBounds` 안
- 왕복 · 레이캐스트 · `PathToWorld` 테스트는 그대로 통과해야 한다
