## 1. 데이터
- `SupportCardData` (SO): id · displayName · category(공격 · 경제 · 방어 · 유틸) · icon(Sprite — A14 납품 전엔 비움) · description(`{value}` 자리) · effects[] · maxStacks · unlockRank · baseWeight · drawCondition
- `CardEffect`: kind(Modifier · Counted · Instant) · stat(기획서 15종) · target(드론 종류 / 전체) · op(Add · Percent) · value · count · activeWave(0 = 항상)
- `SupportCardPool` (SO): cards[]
- Data → Core 변환 (`SupportCardSpec` · `CardEffectSpec`, readonly struct) — 기존 `GameDataSet` 변환 흐름에 맞춤
- 16장 SO 값 = 기획서 「카드 목록」 표 그대로. C09 · C10 · C11 = unlockRank 사원

## 2. RunModifiers · StatResolver
- RunModifiers: 고른 카드 · 중첩 · 횟수형 남은 횟수 · `Changed` 이벤트(C# event). 판 끝 `Clear()`
- StatResolver: `Get(DroneType, StatKey, baseValue)` = `(base + ΣAdd) × (1 + ΣPercent)` · 백분율끼리 더함 · 상한 (Damage +50% · AttackInterval −30% · Range +1 · SlowRate ≤ 70% · SummonCost ≥ 10) · activeWave 적용 (현재 웨이브 인자)
- **캐시**: 보정값 · 웨이브가 바뀔 때만 다시 계산 → 조회는 할당 0
- 횟수형 소모 API: `TryConsume(StatKey)` (C05 · C13 · C14 · C15 · C16) · 우선순위 규칙 (C16 무료가 C05 할인보다 먼저, 기획서 예외 표)
- 즉시형(C06 · C08 · C09)은 RunModifiers 에 「적용 요청」 으로만 남기고 실제 코인 · HP · 드론은 G13 이 처리 (Core 는 값만)

## 3. SupportCardDrawer (순수 C#)
- 기획서 「뽑기 규칙」 1~5 · 제외 조건 · 가중치 표 그대로. `DrawContext` = 해치 HP · 최대 · 빈 칸 수 · 종류별 드론 수 · 직급 · 이미 고른 중첩
- 판 시드 (`IRandom` — 웨이브 스케줄 시드와 **분리**, V01 8장 시드 규칙에 한 줄 추가 보고)
- 다시 뽑기 API (잠금 상태여도 코드 · 테스트는 있음)

## 테스트 (EditMode — 기획서 「테스트 · 완료 기준」)
- 시드 1,000개: 중복 0 · 분류 2가지 이상 100% · 제외 조건 위반 0
- HP 5 이하 → C08 항상 포함 · HP 20 → C08 없음 · 빈 칸 0 → C09 없음 · 인턴 → C09 · C10 · C11 없음
- 다시 뽑기 → 방금 3장 안 나옴 (부족하면 다시 넣음)
- StatResolver: 45 → 54 → 63 (C01 두 장) · 상한 · C12 웨이브 3 에서만 · 조회 할당 0
- 횟수형: C05 두 장 = 6회 · 할인 15 그대로 · 비용 최소 10 · C16 이 C05 보다 먼저
- 같은 시드 + 같은 선택 → 같은 카드
