## 만들 것

### 1. 어셈블리 정의 8 + 1개
| asmdef | 경로 | 참조 | 특이 설정 |
|---|---|---|---|
| `QL.Core` | `02_Scripts/Core/` | 없음 | **`noEngineReferences: true`** |
| `QL.Data` | `02_Scripts/Data/` | QL.Core | — |
| `QL.Game` | `02_Scripts/Game/` | QL.Core · QL.Data · DOTween.Modules · Unity.InputSystem | — |
| `QL.UI` | `02_Scripts/UI/` | QL.Game · QL.Core · QL.Data · Unity.TextMeshPro · DOTween.Modules · Unity.InputSystem | — |
| `QL.FX` | `02_Scripts/FX/` | QL.Game · QL.Core · QL.Data · DOTween.Modules | — |
| `QL.Audio` | `02_Scripts/Audio/` | QL.Game · QL.Core | — |
| `QL.DebugTools` | `02_Scripts/Debug/` | QL.Game · QL.Core · Unity.InputSystem | `defineConstraints` 없음 (코드 안에서 `#if`) |
| `QL.Editor` | `02_Scripts/Editor/` | QL.Core · QL.Data | `includePlatforms: [Editor]` |
| `QL.Tests.EditMode` | `Tests/EditMode/` | QL.Core · QL.Data · `UnityEngine.TestRunner` · `UnityEditor.TestRunner` | `includePlatforms: [Editor]`, `overrideReferences: true` + `nunit.framework.dll`, `defineConstraints: [UNITY_INCLUDE_TESTS]` |

- 네임스페이스 루트 = asmdef 이름 (각 asmdef 의 `rootNamespace` 에 넣는다)
- **의존은 표의 방향만.** Core 가 다른 것을 참조하거나, Game 이 UI 를 참조하면 안 된다

### 2. DOTween 모듈 asmdef
`DOTween.dll` 자체는 모든 어셈블리가 자동 참조하지만, `DOFade` · `DOColor`(UI · Material) 같은 **모듈 확장은 `Modules/*.cs` 소스**라 asmdef 를 가진 코드에서 보이지 않는다.
- Unity 메뉴 `Tools > Demigiant > DOTween Utility Panel` → **Create ASMDEF** 를 누른다 (Unity MCP 메뉴 실행 또는 사람에게 요청)
- 생긴 `DOTween.Modules.asmdef` 하나만 소유 파일이다. 모듈 `.cs` 내용은 고치지 않는다
- 패널의 모듈 체크는 **UI · TextMeshPro · Physics 끔 없이 기본값 유지**

### 3. `CoreInfo.cs` — Core 가 엔진 없이 컴파일되는지 확인용
```csharp
namespace QL.Core
{
    public static class CoreInfo
    {
        public const string Name = "QL.Core";
    }
}
```

### 4. `SmokeTests.cs`
```csharp
using NUnit.Framework;
using QL.Core;

namespace QL.Tests.EditMode
{
    public class SmokeTests
    {
        [Test]
        public void CoreInfo_Name_IsCoreAssembly()
        {
            Assert.AreEqual("QL.Core", CoreInfo.Name);
        }
    }
}
```
