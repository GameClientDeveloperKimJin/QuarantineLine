## 목표
시스템 기획서의 수치를 **ScriptableObject 에셋**에 넣고, Core 가 그 값을 엔진 없이 쓸 수 있게 **불변 구조체**로 바꾸는 길을 만든다.
규칙(머지 · 소환 · 웨이브)은 아직 만들지 않는다. L03~L07 이 이 구조체만 보고 규칙을 짠다.

```
[SO 에셋] UnitData ──ToStats()──► UnitStats (Core, readonly struct)
          EnemyData ─────────────► SlimeStats
          WaveData ──────────────► WaveSpec[] (WaveEntrySpec[])
          GameConfig ────────────► RuleConfig
          GameDataSet  = 위 전부를 묶은 입구 1개 (G01 Bootstrap 이 이것 하나만 참조)
```

## 만들 것

### 2. Core 구조체 — `QL.Core.Stats`
전부 `public readonly struct`, 생성자에서 모든 값을 받는다. 시각 정보(프리팹 · 색)는 **넣지 않는다** — Core 는 화면을 모른다.

| 구조체 | 필드 |
|---|---|
| `UnitStats` | `DroneType type` · `int grade` · `AttackKind attackKind` · `int damage` · `float attackInterval` · `float range` · `float slowRate` · `float slowDuration` · `int pierceCount` · `int coneLaneSpread` · `float burnDps` · `float burnDuration` · `float freezeInterval` · `float freezeRadius` · `float freezeDuration` |
| `SlimeStats` | `SlimeType type` · `int maxHp` · `float moveSpeed` · `int hatchDamage` · `int reward` |
| `WaveEntrySpec` | `SlimeType slime` · `int count` · `float spawnInterval` · `float startRatio` |
| `WaveSpec` | `WaveEntrySpec[] entries` · `float prepTime` · `int clearBonus` · `string bannerText` |
| `RuleConfig` | `int laneCount` · `int rowCount` · `float pathLength` · `float cellSize` · `int hatchMaxHp` · `int hatchCriticalHp` · `int startCoin` · `int summonBaseCost` · `int summonCostStep` · `float mergeLockDuration` · `float contaminateDuration` · `int cleanReward` · `int randomSeed` |

- `pierceCount` = **한 번 공격에 맞히는 마리 수**. 관통 없음 = 1
- `coneLaneSpread` = 자기 레인 양옆으로 몇 레인까지. 자기 레인만 = 0
- `burnDps` · `freezeInterval` 등 해당 없으면 0

### 3. `Core/Units/UnitCatalog.cs` — `QL.Core.Units`
머지 결과를 `(type, grade + 1)` 로 찾는 유일한 곳 (`V01` 4장 — 머지 테이블 없음).
```csharp
public sealed class UnitCatalog
{
    public UnitCatalog(IReadOnlyList<UnitStats> units);   // 검증 실패 시 ArgumentException
    public bool TryGet(DroneType type, int grade, out UnitStats stats);
    public UnitStats Get(DroneType type, int grade);       // 없으면 KeyNotFoundException
    public int MaxGrade(DroneType type);                   // 데이터에서 계산 — 3 을 코드에 쓰지 않는다
    public bool CanUpgrade(DroneType type, int grade);     // grade < MaxGrade(type)
}
```
생성자 검증: 같은 `(type, grade)` 중복 → 예외 / 어떤 종류의 등급이 1 부터 빈틈없이 이어지지 않음 → 예외 / `DroneType` 의 모든 값이 하나 이상 있어야 함.

### 4. Data — `QL.Data` SO 5종 + 에셋 14개
각 SO 에 `[CreateAssetMenu(menuName = "QL/…")]`, 직렬화 필드는 `[SerializeField] private` + 읽기 프로퍼티. 각 SO 에 Core 변환 메서드 하나 (`ToStats()` · `ToSpecs()` · `ToRuleConfig()`).

| SO | Core 로 안 가는 시각 필드 |
|---|---|
| `UnitData` | `GameObject prefab` · `Color tintColor` |
| `EnemyData` | `GameObject prefab` · `float scale` |
| `WaveData` | — (`waves` 배열: `entries[] { EnemyData slime, count, spawnInterval, startRatio }`, `prepTime`, `clearBonus`, `bannerText`) |
| `GameConfig` | — |
| `GameDataSet` | 참조 묶음: `UnitData[] units` · `EnemyData[] enemies` · `WaveData waves` · `GameConfig config`. `BuildCatalog()` · `GetEnemy(SlimeType)` 제공 |

`WaveData` 의 `entries.slime` 은 `EnemyData` 참조로 두고 `ToSpecs()` 에서 `SlimeType` 으로 바꾼다 (인스펙터에서 끌어다 놓게).

## 숫자를 코드에 쓰지 않는다
- `3`(최대 등급) · `15`(칸 수) · `5`(레인) 같은 기획 수치를 `.cs` 에 적지 않는다. 최대 등급은 `UnitCatalog.MaxGrade`, 칸 수는 `RuleConfig` 로 계산
- 테스트의 **검증 경계값**(`> 0`, `[0, 1)`)은 수치가 아니라 규칙이므로 예외
- SO 필드 기본값(필드 초기화)도 0 · null 로 둔다. 값은 에셋에만

## 금지 사항
- ❌ `QL.Core` 에 `UnityEngine` (`Color` · `GameObject` · `Mathf` 포함) — 엔진 참조가 막혀 있다
- ❌ 머지 · 소환 · 웨이브 시간 계산 같은 **규칙** — L03~L07 이다
- ❌ SO 에 `MonoBehaviour` 로직, 런타임에 SO 값을 바꾸는 코드 (`private set` 없이 읽기 전용)
- ❌ `Resources.Load` 로 읽게 만드는 것 — `04_Resources` 는 Unity 의 `Resources` 폴더가 아니다. 참조는 `GameDataSet` 직렬화 필드로
- ❌ `prefab` 에 임시 프리팹을 만들어 넣는 것 — R3 몫
- ❌ `Assets/Settings/SampleSceneProfile.asset` 삭제 — RP 에셋이 참조 중이다. U07 에서 R4 가 정리
