## 목표
시스템 기획서 「소환」 · 「경제」 · 예외 처리 표의 소환 연타 규칙을 화면 없이 판정한다.
G03(소환 버튼 · Space)은 `Summoner.TrySummon` 하나만 부르고, 돌려받은 결과로 드론 모델을 만들고 `GameEvents` 를 낸다.

```
Summoner (상태: 소환 횟수 n)
 ├ CurrentCost            = SummonRule.CostOf(config, n)      = summonBaseCost + summonCostStep × n
 ├ Check(grid, wallet)    → SummonBlock (None · NoCoin · NoCell)
 └ TrySummon(grid, wallet, rng) → SummonResult
        Check → 빈 칸 무작위 1개 → 종류 무작위 1개 → wallet.TrySpend → grid.Place(cell, type, 1) → n++
Wallet (상태: 코인)  — 소환 · 처치 보상(L06/G05) · 웨이브 보너스(L07/G06)가 함께 쓴다
```

## 만들 것

### 1. 난수 — `QL.Core` (`V01` 8장)
```csharp
public interface IRandom
{
    int Next(int maxExclusive);          // 0 ≤ 값 < maxExclusive. maxExclusive ≤ 0 이면 ArgumentOutOfRangeException
}

public sealed class SeededRandom : IRandom   // System.Random(seed) 감싼 것. G01 Bootstrap 이 config.RandomSeed 로 만든다
```
- 이 프로젝트의 모든 무작위(소환 · L05 레인 · O01 오염 칸)는 `IRandom` 하나로만 뽑는다

### 2. `Economy/Wallet.cs` — `QL.Core.Economy`
```csharp
public sealed class Wallet
{
    public Wallet(int startCoin);        // < 0 이면 예외
    public int Coins { get; }
    public bool CanAfford(int cost);     // Coins >= cost
    public bool TrySpend(int cost);      // 모자라면 false, 아무것도 안 바뀜. cost < 0 이면 예외
    public void Add(int amount);         // amount <= 0 이면 ArgumentOutOfRangeException
}
```
- **이벤트를 만들지 않는다** (L03 과 같은 원칙 — Core 는 반환값으로만 알린다). G03 이 소비 · 획득 직후 `GameEvents.CoinChanged(now, delta)` 를 낸다
- 코인은 웨이브 사이에 이월된다 — Wallet 은 웨이브를 모른다. 초기화는 새 판에서 새 Wallet 생성으로

### 3. `Economy/SummonBlock.cs`
```csharp
public enum SummonBlock { None, NoCoin, NoCell }
```
**둘 다 해당하면 `NoCell`** (R1 결정 — 「칸이 가득 찼습니다」가 "머지로 칸을 비워라"는 할 일을 알려 준다. 시스템 기획서 예외 표 「모든 칸이 가득 참 → 머지로 칸 확보 유도」)

### 4. `Economy/SummonRule.cs` — 비용 공식만, 정적
```csharp
public static class SummonRule
{
    public static int CostOf(in RuleConfig config, int summonCount);   // summonBaseCost + summonCostStep × summonCount. summonCount < 0 이면 예외
}
```

### 5. `Economy/SummonResult.cs`
```csharp
public readonly struct SummonResult
{
    public bool Success { get; }
    public SummonBlock Block { get; }   // Success 면 None
    public int Cell { get; }            // 실패면 -1
    public DroneType Type { get; }      // 실패면 의미 없음
    public int Grade { get; }           // 성공이면 1, 실패면 0
    public int CostPaid { get; }        // 실패면 0
    public int NextCost { get; }        // 처리 후의 CurrentCost (UI 가 바로 비용 숫자를 갱신 — 예외 표 「비용은 소환 직후 갱신」)
}
```

### 6. `Economy/Summoner.cs`
```csharp
public sealed class Summoner
{
    public Summoner(RuleConfig config, UnitCatalog catalog);
    public int SummonCount { get; }                         // 성공한 소환 횟수. 머지 · 드론 소멸로 줄지 않는다
    public int CurrentCost { get; }
    public SummonBlock Check(GridModel grid, Wallet wallet);
    public SummonResult TrySummon(GridModel grid, Wallet wallet, IRandom rng);
}
```
**`TrySummon` 순서 — 순서를 바꾸지 않는다 (같은 시드 = 같은 결과)**
1. `Check` — `None` 이 아니면 실패 결과를 돌려준다. **난수를 뽑지 않고**, 아무것도 바꾸지 않는다
2. 빈 칸 후보 = `HasDrone == false` 이고 `IsContaminated == false` 인 칸을 **인덱스 오름차순**으로 모은다
3. `cell = 후보[rng.Next(후보 수)]` — 난수 1번째
4. `type = 종류목록[rng.Next(종류 수)]` — 난수 2번째. 종류목록 = `DroneType` 전체를 정의 순서로 (각 1/3)
5. `wallet.TrySpend(CurrentCost)` → `grid.Place(cell, type, 1)` → `SummonCount++`
6. 성공 결과 반환 (`NextCost` = 증가 후 비용)

- 1등급 = `1` 은 기획 수치가 아니라 「소환은 최저 등급」이라는 규칙이다. `catalog` 로 1등급이 있는지 생성자에서 확인한다 (없으면 예외)
- 후보 버퍼 · 종류목록은 **생성자에서 한 번만** 만든다 (`TrySummon` 안에서 `new` · LINQ 금지 — `V01` 6장, 3웨이브 중에도 소환한다)
- 「한 프레임 1회」 연타 가드는 **G03 몫**이다. 여기서는 부를 때마다 판정한다
- 드래그 중인 원래 칸은 드론이 있으므로 자동으로 후보에서 빠진다 (L03 `GridModel`)
