## 목표
`WaveSpec` 하나 → **시각 오름차순 `SpawnEvent[]`**. G04(점액 스폰)는 이 표를 앞에서부터 꺼내기만 하고, P04(웨이브 미리보기 툴)는 `WaveSummary` 를 **그대로 호출**해 인스펙터에 보여 준다. 시간 계산이 두 곳에 생기지 않게 하는 작업이다.

```
WaveSpec ──WaveSchedule.Build(spec, config, rng)──► SpawnEvent[]  (time 오름차순, 웨이브 시작 = 0초)
         ──WaveSchedule.Summarize(spec, slimes)──► WaveSummary   (총 마리 · 총 HP · 처치 보상 합 · 클리어 보너스 · 마지막 스폰 시각)
SpawnEvent[] ──SpawnCursor──► Advance(dt) 후 TryNext(out e) 로 "지금까지 나올 차례인 것"을 하나씩
```

## 시간 규칙 — R1 결정

| 값 | 공식 |
|---|---|
| 항목 길이 `L(e)` | `e.Count × e.SpawnInterval` |
| 웨이브 기준 길이 `D` | 모든 항목의 `L(e)` 중 최댓값 |
| 항목 시작 `S(e)` | `e.StartRatio × D` |
| `i` 번째 스폰 (`i = 0 … Count-1`) | `S(e) + i × e.SpawnInterval` |

검산 (L02 에셋 값, **테스트에 쓰지 않는다** — 설명용)
| 웨이브 | D | 결과 |
|---|---|---|
| 2 | 덩어리 25 × 0.8 = 20 | 변이 점액 13.2 · 14.0 · 14.8초 → 「후반 1/3」 |
| 3 | 덩어리 24 · 변이 8 × 3.0 = 24 | 변이 점액 0 · 3 · … · 21초 → 「전체에 고르게」 |

- 준비 시간(`PrepTime`)은 시간표에 넣지 않는다. 시간표는 **웨이브 시작 = 0초** 기준이고, 준비 → 웨이브 전환은 L07
- 레인은 스폰마다 `rng.Next(laneCount)` — 시스템 기획서 「무작위 레인」

## 만들 것 — 네임스페이스 `QL.Core.Waves`

### 1. `SpawnEvent.cs`
```csharp
public readonly struct SpawnEvent
{
    public float Time { get; }       // 웨이브 시작부터 초
    public SlimeType Slime { get; }
    public int Lane { get; }         // 0 … laneCount-1
    public int EntryIndex { get; }   // 어느 항목에서 나왔나 (정렬 · 디버그용)
}
```

### 2. `WaveSchedule.cs` — 정적, 상태 없음
```csharp
public static class WaveSchedule
{
    public static SpawnEvent[] Build(in WaveSpec spec, in RuleConfig config, IRandom rng);
    public static float BaseDuration(in WaveSpec spec);                                  // D
    public static WaveSummary Summarize(in WaveSpec spec, IReadOnlyList<SlimeStats> slimes);
}
```
**`Build` 순서 — 바꾸지 않는다 (같은 시드 = 같은 표)**
1. 위 공식으로 모든 스폰의 `Time` 을 계산한다 (레인은 아직 비움)
2. 정렬: `Time` 오름차순 → 같으면 `EntryIndex` 오름차순 → 같으면 `i` 오름차순 (**안정 정렬**. 같은 시각 동시 스폰 허용 — 덩어리와 변이 점액이 0초에 함께 나올 수 있다)
3. **정렬된 순서대로** 레인을 하나씩 `rng.Next(config.LaneCount)` 로 뽑는다
4. 배열 반환

- `Count == 0` 항목은 건너뛴다. `Count < 0` · `SpawnInterval <= 0` · `StartRatio` 가 `[0, 1]` 밖이면 `ArgumentException`
- `Build` 는 **웨이브 시작 때 한 번** 부른다. 그래서 배열 `new` 는 허용한다 (매 프레임 아님). 대신 `SpawnCursor` 는 할당 0

### 3. `WaveSummary.cs`
```csharp
public readonly struct WaveSummary
{
    public int SlimeCount { get; }        // 총 마리 (G06 「남은 점액」 초기값 · L07 웨이브 종료 판정)
    public int TotalHp { get; }           // Σ count × maxHp
    public int KillReward { get; }        // Σ count × reward
    public int ClearBonus { get; }        // spec.ClearBonus
    public float LastSpawnTime { get; }   // 마지막 스폰 시각 (항목이 없으면 0)
    public float BaseDuration { get; }    // D
}
```
- `slimes` 에 해당 `SlimeType` 이 없으면 `KeyNotFoundException`
- P04 미리보기는 이 값들을 표로 보여 준다 — **P04 가 다시 계산하지 않는다**

### 4. `SpawnCursor.cs` — 런타임 꺼내기, 할당 0
```csharp
public sealed class SpawnCursor
{
    public SpawnCursor(SpawnEvent[] schedule);
    public float Elapsed { get; }
    public int Remaining { get; }                  // 아직 안 꺼낸 개수
    public bool IsFinished { get; }                // Remaining == 0
    public void Advance(float dt);                 // dt < 0 이면 예외
    public bool TryNext(out SpawnEvent e);         // Time <= Elapsed 인 다음 것을 하나 꺼냄. 없으면 false
}
```
- G04 사용 예: `cursor.Advance(dt); while (budget-- > 0 && cursor.TryNext(out var e)) Spawn(e);` — 한 프레임에 몇 마리까지 낼지(프레임 분산)는 **G04 가 정한다**. 커서는 밀린 것을 다음 프레임에 계속 돌려준다
- 감속 · 일시정지는 G04 가 `dt` 로 처리 (`Time.timeScale = 0` 이면 `dt = 0`)
