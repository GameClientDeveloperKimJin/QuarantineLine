## 목표
시스템 기획서 「게임 상태 흐름」 · 「격리 해치 · 승패」 · 「적 · 웨이브」(준비 시간 · 웨이브 종료) · 예외 표 1행(동시 발생 → **패배 우선**)을 판정한다.
G06(한 판 흐름)은 프레임 중에 일어난 일을 `Notify…` 로 알리고, 프레임 끝에 `Tick` 한 번을 불러 **이번 프레임에 바뀐 것**을 `FlowStep` 으로 받아 `GameEvents` 로 내보낸다. Core 는 이벤트를 만들지 않는다 (L03 이후 원칙).

```
                StartGame()                      준비 끝
   Title ───────────────────► Prep(0) ──────────────────► Wave(0)
                                ▲                           │ 남은 점액 0 (해치 살아 있음)
                                │ 다음 웨이브 준비            ▼
                                └──────────── 웨이브 클리어 ─┤ 마지막 웨이브였으면 → Result(Victory)
                                                            │ 해치 HP 0 → Result(Defeat)   ← 웨이브 중에만
   Prep · Wave ──Pause()──► Paused ──Resume()──► 원래 상태
```

## 만들 것 — 네임스페이스 `QL.Core.Flow`

### 1. `HatchModel.cs`
```csharp
public sealed class HatchModel
{
    public HatchModel(int maxHp, int criticalHp);   // maxHp <= 0 · criticalHp < 0 · criticalHp >= maxHp 면 예외
    public int MaxHp { get; }
    public int Hp { get; }
    public bool IsBroken { get; }                   // Hp <= 0
    public bool IsCritical { get; }                 // 0 < Hp <= criticalHp  (HUD 붉게 점멸 · 경고등)
    public int TakeDamage(int damage);              // damage <= 0 이면 예외. Hp 는 0 아래로 내려가지 않는다. 실제 깎인 양 반환
}
```
- 웨이브 사이에 회복하지 않는다 (시스템 기획서)

### 2. `GameOutcome.cs`
```csharp
public enum GameOutcome { None, Victory, Defeat }
```

### 3. `FlowStep.cs` — `Tick` 한 번 동안 바뀐 것 (readonly struct, 할당 없음)
| 필드 | 뜻 | G06 이 낼 이벤트 (`V01` 5장) |
|---|---|---|
| `bool StateChanged` · `GameState State` | 상태가 바뀌었으면 새 상태 | `StateChanged` |
| `bool PrepSecondChanged` · `int PrepSecondsLeft` | 준비 중 남은 **올림 초**가 바뀜 (8 → 7 …) | `PrepTick` |
| `bool WaveStarted` · `int WaveIndex` · `int WaveCount` · `string BannerText` | 웨이브 시작 | `WaveStarted` |
| `bool WaveCleared` · `int ClearBonus` | 방금 웨이브를 막음 (마지막 웨이브 포함) — 보너스는 G06 이 `Wallet.Add` | `CoinChanged` |
| `GameOutcome Outcome` | `None` 이 아니면 이번 Tick 에 판이 끝남 | `GameEnded` |
한 Tick 에 여러 개가 동시에 참일 수 있다 (예: 웨이브 클리어 + 다음 준비 상태 진입).

### 4. `GameFlow.cs`
```csharp
public sealed class GameFlow
{
    public GameFlow(in RuleConfig config, WaveSpec[] waves);   // waves 비면 예외
    public GameState State { get; }
    public GameOutcome Outcome { get; }
    public HatchModel Hatch { get; }
    public int WaveIndex { get; }               // 0 부터. Prep 중이면 다음에 시작할 웨이브
    public int WaveCount { get; }
    public float PrepRemaining { get; }
    public int RemainingInWave { get; }         // 이번 웨이브에서 아직 처리 안 된 점액 수 (스폰 전 포함)
    public int SlimesKilled { get; }            // 판 전체 처치 수 (결과 화면)

    public void StartGame();                     // Title → Prep(0). 다른 상태에서 부르면 예외
    public void NotifySlimeKilled();             // Wave · Paused(웨이브 중 멈춤)에서만. 그 밖이면 예외
    public void NotifySlimeReachedLine(int hatchDamage);   // 같은 조건. 해치 피해 + 남은 수 -1 (보상 없음)
    public bool Pause();                         // Prep · Wave 에서만 true
    public bool Resume();                        // Paused 에서만 true, 멈추기 전 상태로
    public FlowStep Tick(float dt);              // dt < 0 이면 예외. Paused · Title · Result 에서는 시간 안 흐름 (빈 FlowStep)
}
```

**`Tick` 판정 순서 — 바꾸지 않는다**
| 순서 | 상태 | 판정 |
|---|---|---|
| 1 | Wave | **해치가 부서졌으면 → Result(Defeat).** 끝 (남은 점액이 0 이어도 패배 — 예외 표 1행 「패배 우선」) |
| 2 | Wave | 남은 점액 0 → 웨이브 클리어(`ClearBonus` = 그 웨이브 `WaveSpec.ClearBonus`). 마지막 웨이브면 → Result(Victory), 아니면 다음 웨이브 Prep 진입 (`PrepRemaining` = 다음 웨이브 `PrepTime`) |
| 3 | Prep | `PrepRemaining -= dt`. 올림 초가 바뀌면 `PrepSecondChanged`. 0 이하가 되면 → Wave 시작 (`RemainingInWave` = 그 웨이브 **Σ entries.Count**, 배너 문구 · 인덱스 채움) |

- **`Notify…` 는 판정하지 않는다.** 숫자만 바꾸고, 판정은 프레임 끝 `Tick` 한 곳에서. 그래서 같은 프레임에 "마지막 점액 처치" 와 "해치 HP 0" 이 순서와 상관없이 함께 와도 항상 패배다
- 패배는 Wave 상태에서만 일어난다 (시스템 기획서 「패배는 웨이브 진행 중에만」). 준비 시간에는 해치 피해가 없다
- 첫 웨이브 준비 8초 · 이후 5초는 **`WaveSpec.PrepTime` 값**이다 (L02 에셋). 코드에 쓰지 않는다
- Prep 에서 남은 시간이 dt 보다 작아 넘친 시간은 버린다 (웨이브는 0초부터 시작 — L05 시간표 기준)
- 「다시 하기」 는 G06 이 **새 `GameFlow` 를 만든다**. Reset 메서드를 만들지 않는다
- 결과 화면의 「최고 등급 드론 수」 는 `GridModel` 에서 G06 이 센다 — 여기서 하지 않는다

## 숫자를 코드에 쓰지 않는다
