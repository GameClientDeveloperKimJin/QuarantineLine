## 이미 있는 것 (L02 · L03 · L04 — 확인만)
- `Cell.IsContaminated` · `CellState.Contaminated` · `GridModel.Contaminate/Clean` (토글만, 타이머 없음)
- `MergeRule`: 오염 칸 위 같은 종류 · 등급 → `MergeClean`, 그 밖 → 거부. `GridModel.Drop` 의 MergeClean 이 오염을 지움
- `Summoner`: 오염 칸에는 소환 안 함
- `RuleConfig.ContaminateDuration` (5) · `CleanReward` (10) — `GameConfig.asset` 값 있음

## 1. 오염 규칙 (기획서 「오염 · 청소」 그대로)
| 규칙 | 값 |
|---|---|
| 언제 | 점액이 해치에 닿을 때마다 (GameFlow 에 `NotifySlimeReachedHatch(lane)` 로 알려지는 그 시점) |
| 어디 | 그 점액 **레인**의 칸 중 아직 오염 안 된 칸 무작위 1칸 (`IRandom`). 레인 전체가 오염이면 무시 |
| 얼마나 | `ContaminateDuration` 5초 → 지나면 자연 청소 (마름) |
| 오염 칸 드론 | 공격 정지 (판정은 O02 — Core 는 `IsContaminated` 만 알려 줌) · 드래그로 꺼낼 수 있음 (꺼내도 칸은 오염 그대로) |
| 소환 | 불가 (이미 있음) |
| 청소 | 오염 칸 위 머지 성공(`MergeClean`) → 즉시 청소. **청소 수당은 바로 주지 않고 그 웨이브 수당 내역에 쌓는다** (아래 3 — R1 결정) |
- `GridModel.Tick(dt)` 에 칸별 오염 남은 시간 감소 추가 (머지 잠금처럼). 0 이 되면 자연 청소
- 이번 프레임에 오염/청소된 칸을 바깥(O02)이 알 수 있어야 한다 — 방법은 구현자 판단 (예: `FlowStep` 에 이번 프레임 오염된 칸 · 자연 청소된 칸 목록을 **미리 만든 배열 + 개수** 로. 할당 금지)
- 웨이브가 끝나면(클리어 · 다음 준비) 남은 오염은? → **그대로 두고 시간 흐름에 맡긴다** (준비 시간에도 Tick). 판이 끝나면 상관없음

## 2. 웨이브 예보 `WaveForecast` (WO-UI-01)
- `readonly struct WaveForecast { int WaveIndex; int SlimeCount; int MutantCount; int CautionLane; }` — `CautionLane` = 변이 점액이 가장 많이 배정된 레인 (동점이면 낮은 번호, **0부터**, 변이 0마리면 −1)
- 순수 함수 `WaveForecast.From(int waveIndex, SpawnEvent[] schedule, int count, int laneCount)` — `WaveSchedule.Build` 결과에서 셈. 할당 없음 (레인별 카운트는 호출자가 준 배열 또는 stackalloc)
- **스폰 순서를 준비 시간 시작 때 미리 만든다** — 지금은 `WaveRunner`(R3)가 웨이브 시작 때 `Build` 한다. 미리 만들어도 결과가 같게 하려면 **웨이브 시간표용 난수를 소환과 분리**해야 한다 (준비 시간 중 소환이 같은 `IRandom` 을 쓰므로 순서가 바뀜). Core 쪽은 「웨이브 시간표 전용 시드에서 웨이브 번호별로 Build」 가 가능한 API 를 준다 (예: `RuleConfig.RandomSeed` + waveIndex 로 만든 별도 `IRandom`). 기존 L05 테스트의 레인 분포 숫자가 바뀌면 고치고 보고에 적는다
- 예보 = 실제 그 웨이브 스폰과 **반드시 같아야 한다** (테스트)

## 3. 수당 내역 `PayBreakdown` (WO-UI-04)
- `readonly struct PayBreakdown { int WaveIndex; int ClearBonus; int CleanCount; int CleanReward; int Total; }` (`CleanReward` = CleanCount × `RuleConfig.CleanReward`)
- `GameFlow` 가 웨이브 중 `MergeClean` 횟수를 센다 → 웨이브 클리어 순간 `Total` 을 **한 번에** 지갑에 넣을 수 있게 `FlowStep` 에 내역을 싣는다 (지금 `ClearBonus` 자리 확장). 지급 자체는 지금처럼 GameLoop(R3) 한 곳
- 청소 집계는 **웨이브 단위** — 준비 시간 중 청소는 다음 웨이브 내역에 넣는다 (단순하게)
- 마지막 웨이브 클리어(승리)도 내역을 만든다 → ResultSummary.BonusEarned 는 Total 합 (O02 에서 GameLoop 가 맞춤)
- 패배한 웨이브의 쌓인 청소 수당은 지급 안 함

## 테스트 (EditMode)
- 오염: 레인 전체 오염이면 무시 · 같은 시드 같은 칸 · 5초 뒤 자연 청소 · Tick 2.5 + 2.5 경계 · 오염 칸 소환 안 됨(기존) · MergeClean 이 청소 + 카운트 1
- 예보: 손으로 만든 시간표에서 SlimeCount · MutantCount · CautionLane (동점 · 0마리 −1) · **예보 = 그 웨이브 실제 Build** (준비 중 소환 여러 번 섞어도)
- 수당: 청소 0 / 2 회 → ClearBonus 50 · Total 50 / 70 · 패배 웨이브 지급 없음 · 마지막 웨이브도 내역
- 할당 0: 웨이브 중 Tick · Notify 반복에 GC 0 (기존 방식)
- 기존 EditMode 전부 통과
