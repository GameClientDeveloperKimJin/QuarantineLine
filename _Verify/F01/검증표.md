# F01 검증표 — 📷 사진 확인 (R1 판정 대기)

Unity MCP(HTTP)로 Game.unity 를 Play 하고 `ScreenCapture.CaptureScreenshot` 로 1920×1080 을 찍었다. 드론은 `Grid.Place` + `DroneBoard.SyncAll` 로 놓았다.
캡처하는 동안 `DragController` · `SummonController` 는 Play 중에만 껐다 (사람 키 입력 차단, 씬 저장 없음). p1 · p2 는 준비 시간이 흐르지 않게 `GameLoop` 도 껐다.
p3 · p4 · p5 는 **진짜 GameLoop 를 실시간으로** 돌렸다 (이벤트 직접 발행 없음). 연속 프레임(p3 · p5)은 캡처 때문에 프레임이 멈추지 않게 첫 프레임부터 `Time.captureFramerate = 60` 을 걸었다 (프레임당 게임 시간 1/60초 고정, 끝나고 0 으로 되돌림).

## ① 머지 판정 실측 (구현 전)
Play 중 빈 칸 0 · 1 에 흡입 1등급 둘을 놓고 `DragController.BeginAt(0)` → `HoverAt(1)` → `ReleaseAt(1)`:
미리보기 칸 1 · 색 (0.25, 1, 0.3) 초록 → **결과 `Merge`** · `DragEnded=Merge` · `DroneMerged` 1회 · 칸 1 = 흡입 2등급 · 칸 0 비움 · 뷰 등급 2.
→ 판정은 정상이다. 원인은 종류를 구분할 수 없는 화면으로 본다.

## ③ 코인 — 수당이 HUD 에 들어간 때 (프레임별 기록, 클리어 프레임부터 2.2초)

`GameLoop.Restart()` 뒤에도 구독 수 그대로 (WaveCleared = PayslipReceipt 1 · CoinChanged 2) — 재시작 경로에서 구독이 끊기지 않는다.
→ 수당은 1.9초까지 붙잡힌다. 사람이 본 「영수증 전에 이미 올라감」 은 지금 코드로는 재현되지 않는다. 영수증 0.45~0.75초에 마지막 처치 코인들이 도착해 숫자가 오르는 것 (R1 조건상 허용) 을 수당으로 봤을 가능성이 크다. 사람 검증은 U14 커밋 82c0480 판이고, 그 뒤 HudCoin · PayslipReceipt · CoinFlyFx · GameLoop 는 바뀌지 않았다 (git diff 0).
