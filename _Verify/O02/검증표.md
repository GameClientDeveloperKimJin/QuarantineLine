# O02 검증표 — 📷 사진 확인 (R1 판정 대기)

Unity MCP(HTTP)로 Game.unity Play (Game 뷰 1920×1080) → `GameLoop.Restart()` 로 새 판 → 바로 `Time.timeScale = 0` → `execute_code` 로 진행 · `ScreenCapture.CaptureScreenshot`.
진행은 테스트와 같은 길: 매 스텝 `Grid.Tick(0.05)` + `GameLoop.Step(0.05)`. 실제 마우스 · Space 가 끼어들지 않게 `DragController` · `SummonController` 컴포넌트만 Play 중 껐다 (흐름 메서드 `BeginAt` · `HoverAt` · `ReleaseAt` 는 그대로 부름, 씬 저장 없음).
판: 레인 1 · 2 · 3 전부(9칸)에 흡입 1등급 (`Grid.Place` + `DroneBoard.SyncCell`) → 웨이브 1 시작 → 레인 1 · 2 · 3 에 변이 점액 1마리씩 (표적) · 레인 0 · 4 웨이브 점액은 매 스텝 처치 (다른 레인 오염 없게)
→ 6.5초 뒤 레인 1 돌파 (점액 Spawn → `Despawn(ReachedLine)` = GameLoop 도달 경로 그대로) → 1.5초 뒤 레인 3 돌파 → 오염 칸 뒤(카메라 쪽) 드론은 빔이 오염 칸 위를 지나가지 않게 바깥 레인으로 옮김 (11 → 10) → 0.5초 더 진행.
측정값은 캡처 직후 `execute_code` 로 읽었다.

## 참고
- 캡처 사이 `Step` 을 부르지 않아 공격 빔 · 데미지 숫자는 p1 마지막 스텝 그대로 남아 있다 (p2 두 장의 빔은 p1 순간의 것).
- 화면 왼쪽 위 보급 코인이 120 으로 보이는 것은 HUD 숫자 트윈(SetUpdate(true), 실제 시간)이 에디터 프레임이 거의 안 돌아 따라오지 못한 것 — 실제 `Wallet.Coins` = 155 (처치 보상 35).
- 오염 칸 표시는 임시 (O03 이 웅덩이 연출로 교체). 판 = 칸 수(15)만큼 Start 에서 한 번 만든 Quad, 켜고 끄기만.
